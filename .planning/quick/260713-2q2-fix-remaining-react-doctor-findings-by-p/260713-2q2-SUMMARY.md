# Quick Task 260713-2q2: Fix Remaining React Doctor Findings by Priority Summary

Closed all 44 triaged react-doctor findings (security -> bugs -> performance -> accessibility -> maintainability) across 27 files, hardening the public contact form with per-IP rate limiting, fixing 20 array-index-key sites, adding `sizes` to all 7 `next/image` fill instances, and breaking a real circular import between `RenderBlocks.tsx` and `Section/Component.tsx`.

## What Was Built

**Security (Tasks 1-2):**
- `JsonLd.tsx`'s `escapeForScriptTag` XSS mitigation confirmed intact (unchanged); doc comment hardened to name the `unsafe-json-in-html` rule explicitly, plus a new standalone regression script (`scripts/verify-jsonld-escape.mjs`) that asserts the escape chain neutralizes `</script>`, `<img onerror>`, and bare `&` payloads.
- `sendContactMessage` (public contact server action) gained a per-IP in-memory rate limit (5 submissions / 10-minute window, keyed off `x-forwarded-for`/`x-real-ip`) on top of its existing honeypot + validation. No new dependency (no Redis) -- relies on this project running as a single persistent Node process on Hostinger.

**Bugs (Tasks 3-7):**
- 20 `key={i}` sites across 11 files replaced with stable keys: Payload row `id ?? i` for CMS array fields, `crumb.url` for the two locally-computed (non-Payload) breadcrumb trails, and a destructure fix in `CallToAction`/`Hero` so the wrapping row's `id` (not the nested `link`'s, which has none) is used as the key. One extra site (`Hero/Component.tsx`'s CTA `links.map`) not explicitly called out in the plan text was caught by Task 5's verify gate and fixed the same way, since it's the identical bug class.
- All 7 `next/image fill` instances now carry a layout-matched `sizes` attribute: full-bleed hero/background images get `100vw`; `AboutSection`'s photo (5/12 column) gets `(min-width: 768px) 41vw, 100vw`; `PostCard`'s thumbnail (1/2/3-col `ArchiveBlock` grid) gets `(min-width: 1024px) 33vw, (min-width: 640px) 50vw, 100vw`.
- `blog/page.tsx` and `contact/page.tsx` now resolve `params`/`searchParams` concurrently via `Promise.all` instead of two sequential awaits.

**Performance (Task 8):**
- `authors/[slug]/page.tsx`: `Intl.DateTimeFormat` instances memoized per locale (2-entry `Map`, es/en) instead of rebuilding on every call.
- `sitemap.html/route.ts` and `ArchiveBlock/Component.tsx`: two-pass `map(...).filter(Boolean)` / `map(...).filter(...)` replaced with a single-pass `flatMap`.
- `HeroGrainGradient.tsx`: dark-mode class read moved from `useEffect` + `useState` (an extra post-mount render, the flash the rule warns about) to `useSyncExternalStore` with a `MutationObserver`-backed subscribe and an SSR-consistent `getServerSnapshot`. Dark mode isn't wired anywhere in this codebase yet, so this is a no-op today, but the pattern is now flicker-safe for whenever it is.
- `search/beforeSync.ts`: category-id lookups in the `for...of` loop replaced with `Promise.all`-driven parallel `findByID` calls, then filtered and merged preserving the original `categories` order (search-index category display order depends on it).

**Accessibility (Task 9):**
- `IconPicker/Component.tsx`'s `autoFocus` removed entirely (no `ref.current.focus()` substitute added).

**Maintainability (Task 10):**
- `badgeVariants`, `buttonVariants`, `navigationMenuTriggerStyle` moved out of `badge.tsx`/`button.tsx`/`navigation-menu.tsx` into new sibling `*-variants.ts` files, so each component file only exports components (Fast Refresh state preservation). No importers existed outside these files, so no other call sites needed updating.
- `IconPicker/Component.tsx`'s 3 large inline style objects (9-10 properties each) had their static parts hoisted to module-scope constants; Tailwind classes were not an option here because the Payload admin route doesn't load this project's `globals.css` (per the 13-01 decision already on record). Only the genuinely stateful parts (`readOnly`'s cursor, `isSelected`'s boxShadow) stay computed per render.
- New `src/blocks/blockRegistry.tsx` extracts the blockType-to-component registry out of `RenderBlocks.tsx`. `SectionComponent` is loaded there via `next/dynamic` (a deferred promise-based import) instead of a static import, because `Section` recursively renders nested blocks through the same registry that also renders `Section` itself -- a genuinely recursive relationship that a same-level type-only extraction can't break. The dynamic import removes `Section/Component.tsx` from `blockRegistry.tsx`'s *static* import graph, which breaks the cycle react-doctor flagged (`RenderBlocks.tsx -> Section/Component.tsx -> RenderBlocks.tsx`) with no runtime behavior change -- confirmed via `npm run build` (all 31 routes generated successfully, admin route unaffected).

| Finding | Disposition | Reasoning |
|---|---|---|
| `unsafe-json-in-html` (`JsonLd.tsx:20` in the final scan, was `:13` pre-change) | Documented false positive | `escapeForScriptTag` escapes `<`, `>`, `&` before injection; react-doctor's static pattern-matcher flags any `JSON.stringify` feeding `dangerouslySetInnerHTML` textually and cannot trace through the wrapper function. Confirmed via `scripts/verify-jsonld-escape.mjs`. |
| `server-auth-actions` (`contact.ts:58`) | Documented false positive on the auth premise; real gap closed | A public contact form is intentionally callable without login -- adding an auth check would break it for every real visitor. The actual missing protection (rate limiting) was added in Task 2. |
| `server-no-mutable-module-state` (`contact.ts:21`, **new finding introduced by Task 2**) | Documented false positive for this deployment model | This rule assumes a serverless/edge deployment where module state doesn't reliably persist between invocations. This project's CLAUDE.md/ARCHITECTURE explicitly targets a single persistent Node process on Hostinger (PM2, `next start`) -- shared module state across requests within that one process is the intended rate-limiter mechanism, not a bug. Documented inline in `contact.ts` so a future scan doesn't "fix" this into defeating the rate limiter. |
