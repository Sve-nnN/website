<objective>
Replace Next.js's native `sitemap.ts` (MetadataRoute.Sitemap convention, which has no way to emit an `<?xml-stylesheet?>` processing instruction) with a custom route handler at `src/app/sitemap.xml/route.ts` that outputs hand-built XML matching the sitemap.org schema, referencing a new static `public/sitemap.xsl` stylesheet so the sitemap renders as a readable table when opened directly in a browser.

Purpose: SITEMAP-01 — `sitemap.xml` currently renders as raw, unreadable XML when opened directly. This plan makes it self-describing and legible without changing what search engines consume (same URL set, same schema).

Output: `src/lib/sitemap-data.ts` (shared query, also consumed by the `sitemap.html` route in plan 15-02), `src/app/sitemap.xml/route.ts` (replaces `src/app/sitemap.ts`), `public/sitemap.xsl`.
</objective>

Also export `SITE_URL` and a `SITEMAP_GROUP_LABELS` map (`pages: 'Pages'`, `blog: 'Blog'`, `'case-studies': 'Case Studies'`, `authors: 'Authors'`, `categories: 'Categories'`) per the Copywriting Contract in 15-UI-SPEC.md, group labels ordered Pages/Blog/Case Studies/Authors/Categories — this exact ordering and label set will be consumed by the `sitemap.html` route in plan 15-02, so keep it stable. `getSitemapEntries()` returns `SitemapEntry[]` in the same document order the collections are queried (Pages, Posts, Case Studies, Authors, Categories) — do not re-sort.

Create `src/app/sitemap.xml/route.ts` following the `src/app/llms.txt/route.ts` route-handler pattern (`export const dynamic = 'force-dynamic'`, `export async function GET()`). Import `getSitemapEntries` from `@/lib/sitemap-data`. Build the XML string manually:
- XML declaration: `<?xml version="1.0" encoding="UTF-8"?>`
- Processing instruction: `<?xml-stylesheet type="text/xsl" href="/sitemap.xsl"?>`
- Root: `<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9" xmlns:xhtml="http://www.w3.org/1999/xhtml">`
- Per entry: `<url><loc>{escaped url}</loc><lastmod>{ISO date}</lastmod><xhtml:link rel="alternate" hreflang="es" href="{escaped es url}"/><xhtml:link rel="alternate" hreflang="en" href="{escaped en url}"/></url>`
- Closing `</urlset>`

Write a local `escapeXml(value: string)` helper (escape `&`, `<`, `>`, `"`, `'`) applied to every URL and date interpolated into the XML — this is untrusted-ish data coming from Payload slugs/titles indirectly via URLs, so escape defensively even though slugs are typically URL-safe. Normalize `lastModified` to ISO 8601 string (`new Date(doc.updatedAt).toISOString()`) before escaping.

Return the XML string via `new Response(xml, { headers: { 'content-type': 'application/xml; charset=utf-8', 'cache-control': 'public, max-age=0, s-maxage=3600, stale-while-revalidate=86400' } })` — mirror the cache-control pattern already used in `llms.txt/route.ts`.

Delete `src/app/sitemap.ts` (the native `MetadataRoute.Sitemap` file this route handler replaces) — Next.js cannot have both a `sitemap.ts` convention file and a `sitemap.xml/route.ts` route handler resolving the same URL; the route handler is now the only source for `/sitemap.xml`.
