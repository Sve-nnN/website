<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| WebsiteCard render -> public HTML | Renders Payload-sourced `website.title`/`website.industry`/`client.name` into JSX — React's default JSX escaping handles this, no `dangerouslySetInnerHTML` involved |
| sitemap-data.ts -> /sitemap.xml, /sitemap.html | Read-only aggregation of published Websites docs into the public sitemap; no new write surface |

## STRIDE Threat Register

This plan is pure additive frontend/utility code with zero new database writes, zero new auth surfaces, and zero new user input handling — it extends existing, already-vetted patterns (CaseStudyCard's JSX-escaping render, buildSectionTrail's pure locale/URL logic, getSitemapEntries' read-only Local API query).

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-39-01 | Information Disclosure | WebsiteCard / sitemap entries | accept | Both only ever query published Websites docs via the existing `authenticatedOrPublished` access control (Phase 38) or the sitemap's own `_status: published` filter — no new read path bypasses this |
| T-39-02 | Tampering | breadcrumbs.ts / sitemap-data.ts pure functions | accept | No DB writes, no user input consumed by either module — both are pure functions over locale/collection constants |
| T-39-SC | Tampering | npm/CLI installs | accept | No new packages installed this plan — component/lib work only |
</threat_model>
