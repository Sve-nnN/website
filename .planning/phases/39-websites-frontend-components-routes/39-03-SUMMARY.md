## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking issue] payload-types.ts needed a matching type update for `tsc` to pass**
- **Found during:** Task 2 verification (`npx tsc --noEmit` failed with `TS2367: comparison ... 'case-studies' and 'websites' have no overlap`)
- **Issue:** The plan's acceptance criteria requires `tsc --noEmit` to exit 0, but `ArchiveBlock`'s generated `relationTo: 'posts' | 'case-studies'` type in `src/payload-types.ts` had not been regenerated to include `'websites'` after the config.ts change — this file is auto-generated by `payload generate:types` and wasn't itself a task target in the plan.
- **Fix:** Rather than running `payload generate:types` (which would read the entire current on-disk collections/blocks/globals state — including a concurrent agent's (39-02) uncommitted, mid-flight edits to `src/globals/FeaturedContent/index.ts`, `src/collections/Pages/index.ts`, and `src/blocks/blockRegistry.tsx`, risking baking in incomplete/unverified state), manually patched only the `ArchiveBlock` interface's `relationTo` and `selectedDocs` union types to add `'websites'` / `{ relationTo: 'websites'; value: number | Website }`. This is scoped identically to what a full regen would produce for this one block, verified by confirming the `Website` interface already exists in `payload-types.ts` (added in Phase 38).
- **Files modified:** `src/payload-types.ts`
- **Commit:** `9e48b3f`
- **Note for orchestrator/next agent:** `src/payload-types.ts` will still need a full `payload generate:types` regen once all concurrent Phase 39 plans (39-02, 39-04) land, to pick up their own schema/type changes (e.g. `FeaturedWebsitesBlock`, `FeaturedContent.featuredWebsites`) — this plan's manual patch only covers ArchiveBlock's slice.

These stem from plan 39-02's concurrent, uncommitted `FeaturedContent` global edit and are out of scope for 39-03 — left untouched, not fixed.
