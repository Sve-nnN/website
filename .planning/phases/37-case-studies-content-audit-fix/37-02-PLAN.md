Current `src/components/CaseStudyResultsChart.tsx` (full file):
```typescript
type ChartRow = {
  label: string
  before: number
  after: number
}

function buildChartRows(metrics: Metric[]): ChartRow[] {
  const rows: ChartRow[] = []
  for (const metric of metrics) {
    const before = parseLeadingNumber(metric.before)
    const after = parseLeadingNumber(metric.after)
    if (before === null || after === null) continue
    rows.push({ label: metric.label, before, after })
  }
  return rows
}

// ...render:
<YAxis tickLine={false} axisLine={false} width={40} tick={{ fontSize: 11 }} />
<ChartTooltip content={<ChartTooltipContent />} />
<Bar dataKey="before" fill="var(--color-before)" radius={4} />
<Bar dataKey="after" fill="var(--color-after)" radius={4} />
```
`parseLeadingNumber()` (already correct, do not modify) parses free-text metric strings ("12,485" -> 12485, "$41K" -> 41000, "3,782ms" -> 3782) into plottable numbers.

**Recommended dual-axis architecture** (per `37-PATTERNS.md`'s documented Recharts constraint: `yAxisId` is assigned per-`<Bar>`, not per-datum, so a single `data={rows}` array with mixed buckets needs each bucket's series as separate `dataKey`s):

1. Extend the row-building step to bucket by magnitude and produce 4 possible numeric keys per row (`beforeLeft`/`afterLeft`/`beforeRight`/`afterRight`), each populated only for the bucket that row belongs to (the other 2 keys stay `undefined` for that row so Recharts renders no bar segment there):
```typescript
type ChartRow = {
  label: string
  beforeLeft?: number
  afterLeft?: number
  beforeRight?: number
  afterRight?: number
}
```

2. Magnitude bucketing (per `37-UI-SPEC.md` Fix 2 algorithm, authoritative): for each row compute `magnitude = Math.max(Math.abs(before), Math.abs(after))`, then `order = Math.floor(Math.log10(magnitude))` (guard `magnitude === 0` -> treat as order `0`, avoid `-Infinity`). Collect the distinct orders across all rows, sort ascending. If there is only 1 distinct order, every row goes to the `left` bucket and `hasRightAxis = false` (no dual-axis, render a single shared `<YAxis>` exactly as today). If there are 2+ distinct orders, find the largest gap between consecutive sorted orders, split there: orders at or below the split -> `left` bucket, orders above -> `right` bucket. Assign each row's `before`/`after` values into `beforeLeft`/`afterLeft` or `beforeRight`/`afterRight` based on its bucket.

3. Render, conditionally including the right axis and right-bucket bars only when `hasRightAxis`:
```typescript
<YAxis yAxisId="left" orientation="left" tickLine={false} axisLine={false} width={40} tick={{ fontSize: 11 }} />
{hasRightAxis && (
  <YAxis yAxisId="right" orientation="right" tickLine={false} axisLine={false} width={40} tick={{ fontSize: 11 }} />
)}
<ChartTooltip content={<ChartTooltipContent />} />
<Bar dataKey="beforeLeft" yAxisId="left" fill="var(--color-before)" radius={4} />
<Bar dataKey="afterLeft" yAxisId="left" fill="var(--color-after)" radius={4} />
{hasRightAxis && (
  <>
    <Bar dataKey="beforeRight" yAxisId="right" fill="var(--color-before)" radius={4} />
    <Bar dataKey="afterRight" yAxisId="right" fill="var(--color-after)" radius={4} />
  </>
)}
```
`chartConfig`/`ChartConfig` needs a config entry per `dataKey` used (`beforeLeft`/`afterLeft`/`beforeRight`/`afterRight`) so `ChartTooltipContent` resolves the right label/color — map `beforeLeft` and `beforeRight` both to `copy.before`/`var(--chart-2)`, `afterLeft` and `afterRight` both to `copy.after`/`var(--chart-1)`, so the tooltip always shows "Before"/"After" (or the ES equivalents) regardless of which axis a bar belongs to. This is the recommended shape per `37-PATTERNS.md` — executor has discretion on exact variable/function naming as long as the axis/series contract below is met.

Colors (unchanged, `37-UI-SPEC.md` Fix 2 axis contract): `before` always `var(--color-before)` (maps to `--chart-2`), `after` always `var(--color-after)` (maps to `--chart-1`), regardless of axis. `X-axis`: `interval={0}` unchanged (all labels always shown).
