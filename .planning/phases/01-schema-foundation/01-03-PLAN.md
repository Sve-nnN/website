<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Public visitor → Authors/Clientes/Testimonials read | All three collections are public-read (credibility/attribution content meant to be seen) |
| Admin session → write access | Create/update/delete require Payload admin auth (default collection behavior when no explicit `access.create` override is set — Payload defaults unset `create`/`update`/`delete` to admin-authenticated) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-01-05 | Elevation of Privilege | Testimonials/Clientes/Authors write access left at Payload defaults (no explicit `create`/`update`/`delete` override) | accept | Payload's default collection access (unset `create`/`update`/`delete`) already requires an authenticated admin session — explicit `authenticated` import is unnecessary boilerplate for these three collections since only `read` is publicly overridden; verified against aprendoclub's identical pattern (`ClientesTrabajados.ts`/`Testimonios.ts` only override `read`) |
| T-01-06 | Tampering | Testimonials `required: true` on name/role/company bypassed via direct API call with malformed payload | mitigate | Payload's field-level `required` validation runs server-side on every create/update through the Local API, REST, and GraphQL — cannot be bypassed by a client omitting the admin UI |
</threat_model>
