## Home Block: `AuditorHighlight` (new Payload block)

**Placement in Home's `content.layout`** (confirmed live order via `curl https://juan-tech.com/`,
2026-09-05): `Hero → ClientLogosBlock ("Con quiénes trabajé") → CodeFixesBlock ("Errores reales…")
→ ServicesShowcase ("Cómo puedo ayudarte") → AboutSection ("Mi enfoque en Consultoría Técnica") →
AuditOfferBlock ("Empecemos por una auditoría técnica", the PAID 600 USD manual audit closing
band) → ContactFormBlock ("Hablemos")`.

Insert the new block **between `ServicesShowcase` and `AboutSection`**, not adjacent to
`AuditOfferBlock`. Two reasons, both load-bearing:

1. Visual family: `ServicesShowcase` is the explicit pattern FEAT-01 requires, so sitting next to
   it (not several sections away) reads as the same design language.
2. Name collision: `AuditOfferBlock`'s heading is literally "Empecemos por una auditoría técnica"
   (the PAID, human-delivered audit, 600 USD, Juan's existing service). The new section is about a
   free automated tool with a similar name. Putting them adjacent invites a visitor to conflate a
   $600 consulting engagement with a free SaaS tool. `AboutSection` sits between them as a buffer.

**Why this is not a whole-card link (unlike `ServicesShowcase`):** `ServicesShowcase` cards are
internal navigation — the whole card is a `<Link>` because it's just routing within the same site.
This card exits to a different domain running someone's own product; an explicit `Button` (not a
tap-anywhere card) makes the domain boundary a deliberate action, not an accidental swipe.

**Fields (`src/blocks/AuditorHighlight/config.ts`):**

| Field | Type | Localized | Required | Notes |
|-------|------|-----------|----------|-------|
| `title` | text | yes | no | Empty → `sr-only` fallback heading, same pattern as `ServicesShowcase.title` (SEO-10.2 precedent: never skip a heading level). |
| `description` | textarea | yes | yes | 1-2 sentences, no line-clamp (this is a single feature block, not a 4-up grid — there is room). |
| `ctaLabel` | text | yes | no | Empty → i18n fallback (`auditorHighlight.cta`). |
| `freeTierNote` | textarea | yes | yes | The honest disclosure — see Copywriting Contract. Renders as visible caption text (`text-label text-muted-foreground`), never `sr-only`, never below-the-fold-only. |

**NOT Payload fields, hardcoded in `src/lib/auditor.ts`** (single source of truth, imported by all
3 surfaces — same pattern as `SERVICE_SLUGS` in `src/lib/service-slugs.ts`): the destination URL
and the 4 verifiable stats. These are facts about a product Juan controls the accuracy of, not
editorial copy — a CMS field would let an editor accidentally inflate a number FEAT-02 requires to
stay literally true.

```

export const AUDITOR_STATS = [

  { value: '5', labelKey: 'statsCategories' },
  { value: '500', labelKey: 'statsUrls' },
  { value: 'CWV', labelKey: 'statsCwv' },
] as const
```

|-----|----|----|

| Field | ES | EN |
|-------|----|----|
| `title` | Construí mi propio auditor SEO | I built my own SEO auditor |

It's not a service I sell, it's software I built and run in production. |

**Layout:** `Card` (same `rounded-2xl border bg-card shadow-sm` as `ServicesShowcase`'s card),
full-width single feature (not part of the services grid). Icon chip (`Gauge` from `lucide-react`,

CTA button: `Button` default variant, label from `ctaLabel` (fallback `t('cta')`), rendered as a
**plain `<a>`** (not `next/link`, not `@/i18n/navigation`'s `Link`, not `CMSLink`) wrapped in
`buttonVariants()` classes — see "Outbound Link Contract" below for why plain `<a>` is mandatory

## Service Landing Block: `AuditorCallout` (new Payload block, `seo-technical-audit` only)

**Why a new block instead of a field on `ServiceScopeCard`:** `ServiceScopeCard` is a shared block
type rendered on all 4 service landings (`seo-technical-audit`, `seo-consulting`,
`fullstack-development`, `ai-seo-geo`). Adding an auditor-specific field there would put an
irrelevant admin field in front of editors working on the other 3 landings, and `ServiceScopeCard`'s
fields are plain `text`/`textarea` (no rich text), so an inline link inside its prose isn't
possible without a schema change to a block used everywhere. A small, dedicated, single-use block
(same pattern already established by `LocalProofSection`/`RelatedCaseStudyBlock` — blocks built for
one specific page) is the lower-risk path: additive migration touching only the new block's own
table, zero risk to the other 3 landings.

**Placement:** confirmed live block order on `/servicios/seo-technical-audit` via curl (2026-09-05):
`Hero → "Tu sitio pierde tráfico y nadie te dice por qué" → ServiceScopeCard ("Alcance de esta
auditoría") → ClientLogosBlock ("Clientes") → Testimonios → RelatedCaseStudyBlock ("Un caso real de
cómo trabajo") → FAQ`. Insert the new callout **immediately after `ServiceScopeCard`, before
`ClientLogosBlock`** — right after the visitor reads what the paid audit covers, before social
proof, framed as "here's a lighter option first."

**Fields (`src/blocks/AuditorCallout/config.ts`):**

| Field | Type | Localized | Required | Notes |
|-------|------|-----------|----------|-------|
| `heading` | text | yes | no | Empty → i18n fallback (`auditorCallout.heading`). |
| `narrative` | textarea | yes | yes | The full pitch — this block has no separate stat row, so the 4 facts are woven into the sentence (see draft copy). |

**Visual treatment:** wraps the existing `StackHighlightCallout` component (no visual
reinvention) — `rounded-lg bg-secondary p-8 text-secondary-foreground`, heading, `Prose` narrative.
**No `badge` prop used.** `StackHighlightCallout`'s optional badge chip exists specifically to mark
the "no-commission pick" inside affiliate context (`/stack`); using it here would visually imply
this callout belongs to that same affiliate taxonomy, which it explicitly does not (this is Juan's
own product, FEAT-01/hard constraint). CTA renders through the same component's external-link slot
(see "Outbound Link Contract"), label from i18n `auditorCallout.cta`, not a field — this block stays
minimal on purpose.

## Outbound Link Contract (hard constraint, applies to all 3 surfaces above)

Every anchor pointing at `https://auditor.juan-tech.com` must satisfy all of the following. This
is a checker-verifiable, per-link checklist — not a paragraph to summarize away.

| Rule | Value | Why |
|------|-------|-----|
| Element | Native `<a>` | `next/link` and `@/i18n/navigation`'s `Link` are client components; `CMSLink` resolves absolute URLs through `next/link` too. FEAT-04 requires 0 KB of added client JS — a plain anchor is the only element that is unconditionally zero-cost regardless of what else is already on the page. |
| `href` | `https://auditor.juan-tech.com` (from `AUDITOR_URL`, one constant, 3 call sites) | Single source of truth — never hand-type the string a second time. |
| `rel` | `noopener` **only** | Never `sponsored` (this is Juan's own product, not an affiliate relationship — applying affiliate `rel` would be factually wrong and would read as one). Never `nofollow` (no reason to block link equity to a site Juan owns). This mirrors the existing precedent already in `StackHighlightCallout`'s GSC link. |
| `target` | `_blank` | The auditor is a separate application (its own login/quota flow); keep the portfolio tab open. |
| Accessible new-tab notice | `sr-only` suffix on the link text: ES "(se abre en una pestaña nueva)" / EN "(opens in a new tab)" | New to this codebase (no existing link currently announces this) — added here as the correct pattern for these 3 new links, not a retrofit of every pre-existing `target="_blank"` link sitewide (out of scope for this phase). |
| Never use | `AffiliateLink` component, `Badge` "no-commission" chip | Both are visual/semantic vocabulary reserved for the affiliate system (Phase 46-48) — this phase is explicitly independent of it (CONTEXT.md: "no `rel=\"sponsored\"`, sin colección `affiliate-links`, sin `/go/`, sin disclosure"). |

**Canonical/hreflang preservation (FEAT-04):** adding a new block instance to a page's
`content.layout` array is a content change, not a route change — it does not touch `canonical.ts`,
`breadcrumbs.ts`, or `sitemap-data.ts`, and does not require touching them. Verify with `git diff`
on those 3 files staying empty at phase close, same gate already used in Phase 48.

**Publish-status gotcha (known incident, not new to this phase):** when the content-population
plan adds these blocks to the live `home`, `seo-technical-audit`, and `stack` docs via the Local
API or admin, it must set `_status: 'published'` (`draft: false`) explicitly — this project has a
recurring bug where bulk/scripted writes silently leave a doc in draft, which self-verifies as
"written" while production keeps serving the old content (see `Websites draft-publish fix` and the
2026-08-17 wrong-database incident in project memory).

## UI Considerations

Applicable state considerations resolved: 4 covered, 2 backstop, 0 unresolved.

The only new UI elements this phase introduces are `static-content` (headings, descriptions, the
stat facts, the free-tier caption) and `interactive-control` (the 3 outbound CTA anchors). No
`form`, `list-collection`, `nav`, or `media` element exists in this phase's scope, so `empty`,
`populated`, `partial`, and `zero-one-many` do not apply to anything introduced here.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|----------------------|
| overflow | static-content (stat labels, description, narrative) | ✅ covered | All 4 stat labels and the description/narrative text wrap normally in their flex/grid containers at 375px — no fixed-width truncation is introduced, same wrap behavior already verified for `ResultsSection`'s stat grid and `StackHighlightCallout`'s `Prose` narrative. |
| long-text | static-content (`description`, `narrative`, `freeTierNote` textareas) | 🧪 backstop | Fields are unbounded `textarea` (no CMS-enforced max length); the Home card's `description` is NOT `line-clamp`'d (unlike `ServicesShowcase`'s card, which has room for only 2 lines) because it is a single full-width feature block, not a 4-up grid slot — an editor entering a very long paragraph will reflow the card taller, never clip or overlap the stat grid on `md:` and up. Needs a held-out visual check at an intentionally long draft value before this can move to `covered`. |
| long-text | interactive-control (`ctaLabel`) | ✅ covered | `ctaLabel` renders inside a `Button`; admin field description caps expectations at 2-3 words (matching `ServicesShowcase`'s "Explorar servicio" precedent) and the button does not force `whitespace-nowrap`, so an outlier long label wraps onto a second line inside the button rather than overflowing it. |
| loading | interactive-control (3 outbound anchors) | ✅ covered | Not applicable by construction: each is a native `<a>` performing a full browser navigation, not a client-side fetch — there is no in-flight state for this component to render. |
| error | interactive-control (3 outbound anchors) | ✅ covered | Not applicable by construction, same reason as `loading` — if `auditor.juan-tech.com` itself is down or slow, that failure belongs to the external app's own UI, not to a fetch this site initiates. |
| overflow | interactive-control (stat grid on Home card at 375px) | 🧪 backstop | 2x2 stat grid must not force horizontal scroll on the Home card at the project's standard 375px mobile-first check — needs the same Playwright 375/768/1280 verification pass already standard for this project (Phase 10.6 precedent), not just a code read. |
