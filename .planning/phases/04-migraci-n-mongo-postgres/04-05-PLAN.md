<field_mapping>
Posts (JuanPortfolio Posts/index.ts -> juan-payload Posts/index.ts):
- title -> title (localizado en ambos)
- tldr (viejo) -> excerpt (nuevo; el nuevo esquema no tiene tldr, excerpt es el campo mas cercano semanticamente -- ambos son resumenes cortos localizados)
- content -> content (richText localizado en ambos; usar remapRichTextMediaRefs(doc.content[locale], remapTable.media) por cada locale antes de escribir -- el dump con locale:'all' trae el richText como objeto {es, en})
- heroImage -> heroImage (remapeado via remapTable.media)
- postAuthors (preferido, relacion a Authors) o authors (fallback, relacion a Users) -> author (nuevo, singular, requerido): usar postAuthors[0] si existe: remapear via getMapping(table,'authors', String(postAuthors[0])); si postAuthors esta vacio, usar authors[0] (relacion vieja a Users, no migrada en esta fase -- no hay remap table para 'users') y en ese caso caer al autor principal conocido del sitio (buscar en authors.json ya migrado un autor cuyo nombre coincida con el usuario, o si no hay match, usar el primer Author migrado como fallback y marcar el post en needsReview) -- documentar la decision tomada en el log
- categories -> categories (hasMany, remapeado via getMapping(table,'categories',...) por cada ID; ids sin mapeo se omiten con warning, no rompen el create)
- publishedAt -> publishedAt (verbatim); usar el mismo valor para decidir _status: 'published' si publishedAt existe, si no dejar draft
- slug -> slug **verbatim**
- Campos viejos sin equivalente nuevo (primaryKeyword, semanticKeywords, relatedPosts, sidebarBanners, searchConsole/gscData, internalLinks*, indexingControl, keywordScorePanel, dinoRankAction, indexStatus, internalLinksCount, noindex, populatedAuthors) -- todos apuntan a tooling interno descartado (KeywordMetrics, AdBanners, GSCMetrics) o son datos derivados que se recalculan en el sitio nuevo; fuera de alcance por diseno de Phase 1, no un recorte de esta fase

Links internos en richText: el viejo LinkFeature con enabledCollections:['pages','posts'] guarda nodos con fields.doc = {relationTo:'posts'|'pages', value: <oldId>}. Como 'pages' no se migra en esta fase (Phase 5 construye las paginas a mano), un link interno a una pagina se deja intacto (no se puede resolver, no es un error). Un link interno a otro post SI se puede resolver una vez existe el remap completo de posts -- por eso la segunda pasada.
