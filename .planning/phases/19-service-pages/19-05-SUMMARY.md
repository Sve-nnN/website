# Phase 19 Plan 05: Seed script assembles + writes all 5 service Pages docs (BLOCKING gate)

**All 5 service pages exist in the real DB with real bilingual content, all 10 URL combinations (index + 4 services, x2 segment spellings) return 200 in both locales, the GEO page links live to /llms.txt and /llms-full.txt — reached only after finding and fixing a real Critical code-review bug (CallToAction bilingual CTA collision) and recovering from a real data-loss incident during that fix's first migration attempt.**

## Performance
- **Tasks:** 2 completed (seed script authoring, blocking live-verification gate) — plus an out-of-plan remediation cycle (code review fix + incident recovery) before the phase could close
- **Files created/modified:** 1 new script, 2 modified (CallToAction block config, its generated migration)

## Accomplishments
- `scripts/seed-phase19-service-pages.ts`: idempotent, upsert-by-slug, assembles Hero/Content/FAQ/CallToAction blocks per locale with positional id-reuse across locale writes (`reapplyIds`, guarded by blockType match per T-19-07). Ran against the real dev DB, twice consecutively (idempotency proven — no duplicate docs, no validation errors).
- Live curl-verified (both before and after the CallToAction fix): all 10 URL combinations (`/servicios`, `/services`, 4x`/servicios/{slug}`, 4x`/services/{slug}`, plus `/en/` prefixed) return 200; invalid slugs 404; sitemap.xml lists the corrected paths.
- **Critical finding (code review, CR-01) and its resolution:** `CallToAction.richText` lacked `localized: true`, so the seed script's distinct per-locale `ctaText` collided on one shared column — all 5 new pages' CTA showed English text even on Spanish routes. Fixed by adding `localized: true` to `src/blocks/CallToAction/config.ts` and generating a migration.
- **Real incident during the fix:** the first migration attempt (auto-generated by `payload migrate:create`) dropped the old shared `rich_text` column without backfilling its existing values into the new locale-specific rows first. Applied once unattended, this wiped CTA copy across the entire DB, including Home's — recovered via Neon point-in-time restore. The migration file was corrected with an explicit backfill step, re-reviewed by a human (Juan, in-thread), and re-applied with explicit approval. `scripts/seed-home-page.ts`, `scripts/seed-phase10-7-gap-fill.ts`, and this phase's own seed script were re-run to restore content.
- This incident produced a lasting, project-wide process improvement: the "Database Safety" section in root `CLAUDE.md`, later relaxed by Juan to gate only destructive operations.
