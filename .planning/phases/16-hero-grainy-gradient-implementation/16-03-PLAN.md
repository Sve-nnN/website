  <files>scripts/verify-hero-grain-gradient.mjs</files>
  <action>
    Create `scripts/verify-hero-grain-gradient.mjs`, modeled on `scripts/verify-mobile-viewport.mjs`'s
    structure (Playwright `chromium.launch()`, one `newPage` per check, `BASE_URL` env override
    defaulting to `http://localhost:3000`, screenshot dir `scripts/.mobile-verify-screenshots`).
    Requires a dev server already running (`npm run dev`) — the script does not spawn one.

    Implement these checks, for each of `/es` and `/en` at viewport 1280x800:
    1. `page.goto` the home route, `waitUntil: 'networkidle'`.
    2. Locate `[data-testid="hero-grain-gradient"]` inside the Hero `section` — assert it is
       present and its `data-motion` attribute equals `"live"` (default OS preference has no
       reduced-motion emulation yet at this point).
    3. Confirm a `<canvas>` element exists inside that wrapper with non-zero
       `boundingBox().width`/`height` — this confirms the shader actually mounted and painted
       an area, not just an empty DOM node.
    4. Best-effort color check: capture `page.screenshot()` of just the Hero section's
       `boundingBox`, decode it in Node via `sharp` (already a project dependency — see
       `scripts/check-hero-overlay-contrast.ts` for the pattern) to compute an average RGB
       across the cropped image. Assert the average stays within a broad dark-navy-family
       range (e.g. average R/G/B all below 90 — the shader's dominant/mid stops are all
       `#12141C`/`#23283A`/`#3A4159`-family dark navy per 16-UI-SPEC.md, with the ember stop
       only a minority weighting) — this is a coarse sanity check that the shader isn't
       rendering solid white/wrong-hue, NOT a pixel-perfect hex match (animated noise makes
       exact-hex assertions unreliable, per this plan's must_haves).
    5. Overflow check at 375/768/1280px (reuse the exact `scrollWidth > viewport.width +
       OVERFLOW_MARGIN_PX` pattern from `verify-mobile-viewport.mjs`).
    6. Content-unchanged check: assert the Hero title (`section h1`) has non-empty text, the
       subtitle (`section p`) has non-empty text if present, and the CTA link (selector from
       Interfaces above) is visible — confirms HERO-ANIM-03 (nothing but the background
       changed).
    7. Reduced-motion check: open a NEW page via
       `browser.newPage({ reducedMotion: 'reduce' })` (Playwright's built-in
       `prefers-reduced-motion` emulation option), navigate to `/es`, and assert
       `[data-testid="hero-grain-gradient"]`'s `data-motion` attribute equals `"reduced"`.
    8. Screenshot every page state to `scripts/.mobile-verify-screenshots/` (home-es-1280.png,
       home-en-1280.png, home-es-375.png, home-es-768.png, home-es-reduced-motion.png at
       minimum) for the written report and for Juan's own final visual pass.

    Print a results table (reuse the note/failure console pattern from the referenced scripts)
    and `process.exit(1)` if any hard assertion fails (canvas presence, overflow, content
    presence, reduced-motion attribute). The color sanity check may log a WARN (not a hard
    FAIL) if outside range, since it's inherently approximate — note this explicitly in the
    script's output.

    Before writing the script, start the dev server (`npm run dev &` or equivalent background
    process) if not already running, run the script against it, and capture its full output for
    Task 2's report.
