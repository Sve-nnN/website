Diferencias clave para este plan (no asumir el mismo where que RelatedPosts):
- Para source === 'latestPosts': collection 'posts', sort: '-publishedAt', where: { _status: { equals: 'published' } }, limit: entry.limit ?? 5.
- Para source === 'latestCaseStudies': collection 'case-studies', sort: '-createdAt' (esta coleccion no tiene publishedAt, confirmado por lectura directa del schema), where: { _status: { equals: 'published' } }, limit: entry.limit ?? 5.
- El filtro _status es obligatorio: el Local API por defecto usa overrideAccess true y NO respeta el access control authenticatedOrPublished de las colecciones, asi que sin este where explicito el footer (visible en TODAS las paginas) podria filtrar borradores a usuarios anonimos.

Tipo Footer.dynamicColumns ya deberia existir en payload-types.ts tras el plan 10.5-02, con la forma: { title?: string, source: 'latestPosts' | 'latestCaseStudies', limit?: number, id?: string }[]

Rutas de destino ya usadas en el codebase (PostCard.tsx, CaseStudyCard.tsx): /blog/${slug} para posts, /case-studies/${slug} para case studies.
