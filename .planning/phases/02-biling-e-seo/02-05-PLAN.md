<interfaces>
Lexical richText fields require a full editor-state JSON shape, not a plain string. Use this exact minimal-paragraph shape (parameterized by `text: string`) everywhere a richText field needs a value (Posts.content, CaseStudies.clientContext, CaseStudies.conclusion):
```
function lexicalParagraph(text: string) {
  return {
    root: {
      type: 'root',
      children: [
        { type: 'paragraph', children: [{ type: 'text', text, version: 1 }], direction: 'ltr', format: '', indent: 0, version: 1 },
      ],
      direction: 'ltr',
      format: '',
      indent: 0,
      version: 1,
    },
  }
}
```

Payload writes are locale-scoped per call — to populate BOTH es and en for a localized field, create the doc with `locale: 'es'` first, then call `payload.update({ collection, id: doc.id, locale: 'en', data: { ...enOnlyFields } })`. Apply this two-call pattern for every doc created below.

CaseStudies required fields recap (src/collections/CaseStudies/index.ts, already read in prior plans): `title` (localized), `kpis` (array, minRows: 1, each `{ label (localized), value }`), `slug`. All other fields optional but `challenge`/`solution`/`results.metrics` items each have their own required subfields IF an item is included — include exactly one item per array to keep the seed minimal while still exercising every field type once: `challenge: [{ text (localized) }]`, `solution: [{ title (localized), description (localized) }]`, `results: { periodBefore, periodAfter, metrics: [{ label (localized), before, after }] }`.

Posts required fields recap (src/collections/Posts/index.ts): `title` (localized), `content` (richText, localized, required), `author` (relationship to authors, required), `slug`.

`redirects` collection (from 02-03 `<interfaces>`): `from` (text, unique), `to: { type: 'custom' | 'reference', url?, reference? }` — no `type` select field (no `redirectTypes` configured in the plugin call).
