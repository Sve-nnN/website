<interfaces>
Current `src/blocks/Hero/Component.tsx` (91 lines) renders a single `<section>` with 2 branches only (`isHome` vs everything else): `isHome` gets `py-16 md:py-24` + `HeroGrainGradient`; every non-home variant (`listing`, `post-header`, `case-study-header`) shares one identical `py-12 md:py-16` treatment plus an optional `absolute inset-0 opacity-30` image overlay when `media` is set. The `isListing` check only gates the breadcrumb `<nav>` block — it does not touch padding/background/border. `variant`, `title`, `subtitle`, `media`, `links`, `breadcrumbs` are the only props (from `HeroBlockProps` in `@/payload-types`); do not add new ones.

Design (do NOT invent alternatives — implement exactly this mapping, keyed by `variant`):

| variant | padding | background overlay (when `media` set) | accent border | notes |
|---|---|---|---|---|
| `home` | `py-16 md:py-24` (unchanged) | `HeroGrainGradient` (unchanged) | none (unchanged) | zero changes to this branch |
| `listing` | `py-10 md:py-14` | none — flat `bg-secondary`, drop the image-overlay entirely for this variant (Blog's seeded Hero has no `media` set today per `28-CONTEXT.md` "Specifics") | `border-b-4 border-primary` (bottom edge) | breadcrumb nav (existing) remains the primary differentiator on top of the new CSS |
| `post-header` | `py-12 md:py-16` (unchanged padding value, kept as today's shared default) | `absolute inset-0 opacity-30` image overlay when `media` set (unchanged behavior) | `border-t-4 border-primary` (top edge) | |
| `case-study-header` | `py-14 md:py-20` (largest of the 3) | `absolute inset-0 opacity-45` image overlay when `media` set (heavier dim than post-header's 30%) | `border-t-8 border-primary` (thicker top edge, double post-header's border width) | |

Use Tailwind's `border-primary` utility (already mapped in `tailwind.config.ts` -> `colors.primary.DEFAULT` -> `var(--primary)`) — no new CSS custom properties needed. `border-b-4`/`border-t-4`/`border-t-8` are standard Tailwind border-width utilities, already available (no `tailwind.config.ts` changes needed).

Implement via a `const variantStyles: Record<HeroBlockProps['variant'], { padding: string; overlayOpacity: string | null; border: string }>` object (or equivalent switch) defined at module scope or top of the component, then spread the looked-up values into the `<section>`'s `className` and the overlay `<div>`'s conditional render. Keep the `isHome`/`HeroGrainGradient` branch exactly as-is — only the non-home path needs restructuring from its current single shared className into a `variantStyles[variant]`-driven one.
