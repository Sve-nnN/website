- Tool category groups: `grid-cols-1 md:grid-cols-2 gap-6` — **two** columns max, not three. Each

- Gear grid (13 Amazon items): `grid-cols-2 sm:grid-cols-3 lg:grid-cols-4 gap-4` — compact items,
  no long-form prose per item, so a denser grid is correct here and reads as "personal kit," not as
  a second tool comparison table.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--background)` / `#FAFAF7` (light) | Page background, all `ToolCard`/`GearCard` surroundings |
| Secondary (30%) | `var(--secondary)` / `#12141C` (light) | `PageHero` band (title/intro), `StackHighlightCallout` surface (both instances — "elegiría hoy" and no-commission pick sit on the navy `bg-secondary text-secondary-foreground` treatment, same as the Lighthouse-score cards on `/websites/[slug]`) |
| Accent (10%) | `var(--primary)` / `#F7581E` (background use) and `var(--primary-text)` / `#D03D07` (text-on-light use) | Reserved for, and only for: (1) the active-affiliate CTA button/link inside `ToolCard`/`GearCard`/the inline block, (2) the no-commission pick's `Badge variant="default"` (the page's single "editorial trust" signal, per the codebase's own documented "One Signal Rule" in `badge-variants.ts`), (3) in-copy accent links inside the 100-word narrative `Prose` blocks (already the sitewide `Prose` link color) |
| Destructive | `var(--destructive)` / `#DC2626` | Not applicable — no destructive user-facing action exists on `/stack` or inside a post's inline block (read-only public content) |

Accent is explicitly **not** used for: category headings, the "no affiliate yet" badge (that one is
neutral `outline`, see below), Gear section chrome, or any full-card background fill. Every
`ToolCard` looks identical in chrome regardless of program — only the CTA slot content changes
between states, which is what keeps the page from reading as a ranked list.

**"No affiliate yet" state (DigitalOcean, Kinsta) — visual contract:**
Same `ToolCard` component, same `Card`/`CardContent` shell, same row structure (Cómo lo uso /
Ventaja / Contra), only the CTA slot differs:
- **Active state:** `AffiliateLink` rendered with `buttonVariants({ size: 'sm' })` className — solid
  accent (`bg-primary text-primary-foreground`) button, label from the doc's `ctaLabel` field.
- **No-affiliate-yet state:** the CTA slot renders `<Badge variant="outline">{copy}</Badge>` instead
  of a button — a neutral, low-emphasis chip (border + `text-foreground`, no fill, no accent). No
  outbound link is rendered at all for this state (DigitalOcean/Kinsta are not linked anywhere from
  their card until Juan has a real affiliate relationship — this avoids any appearance of an
  existing business relationship before one exists, and avoids an unstyled bare link that would read
  as a bug). The rest of the card (name, narrative, pro, con) renders in full, at the same visual
  weight as every other card — the *only* difference readers see is "this one has a chip instead of
  a button," never "this one is missing something" or "this one is disabled/greyed out." Do not use
  `opacity-50`/disabled styling on the card itself — the tool is fully real, only the monetization
  link is pending.

## Component Contract Detail (traceability for planner/executor)

### `ToolStack` block (`src/blocks/ToolStack/{config.ts,Component.tsx}`)
- Registered as the 14th block in the Pages collection's consolidated block array (`src/collections/Pages/index.ts` or wherever `blocks:` is declared), and in the `RenderBlocks` registry (`src/blocks/blockRegistry.ts` or equivalent), same wiring every other Pages block already follows.
- Mounted on a `pages` doc with `slug: 'stack'` — reuses the existing `pages` route pipeline (`[locale]/[slug]`), which already resolves `meta`/canonical/hreflang generically. This is why STACK-01's "no tocar `sitemap-data.ts`/`canonical.ts`/`breadcrumbs.ts`" constraint is naturally satisfiable: a `pages` doc gets sitemap/canonical/hreflang for free from the existing generic pipeline, no new special-case code.
- Content shape the UI needs (exact Payload field names are the planner's call, this is the shape, not the schema):
  - `intro` (localized textarea/richText) — short lede under the `<h1>`, before the disclosure mount.
  - `categoryGroups[]` — ordered array, each with a `heading` (localized text, editor-overridable, defaults from the Copywriting table) and `tools[]`. **Order within `tools[]` is the editorial array order in Payload (drag-and-drop in admin) — never derived from `affiliateLink != null` or commission rate.** An "active affiliate first, no-affiliate last" sort inside a group would read as an implicit ranking even with identical card chrome — explicitly disallowed.
  - `tools[]` (nested inside a group) — each row: `affiliateLink` (relationship to `affiliate-links`, nullable — null is what drives the "no affiliate yet" chip state), `narrative` (localized textarea, ≥100 words, enforced editorially not by a `minLength` validator since word count spans prose that a hard character-count would fight), `pro` (localized text), `con` (localized text, nullable — nullable is what drives the honest-empty con copy), `referenceLink` (a link — either a `relationship` to `case-studies` or a plain href to a service page, both resolving through the same "Dónde lo usé" row).
  - `gearIntro` (localized textarea, one shared paragraph for the whole Amazon program — not per-item).
  - `gearItems[]` — each row: `name` (text, not localized — product names don't translate), `href` (text — the resolved `amzn.to` → full product URL with `tag=juantech02-20`, never the raw shortlink, per 48-CONTEXT.md's hard constraint).
  - `elegiriaHoy` (localized textarea/richText) — feeds `StackHighlightCallout` instance 1.
  - `noCommissionPick` (relationship to `affiliate-links`, expected to resolve to the Google Search Console doc, which itself has no `destinations` — see below) — feeds `StackHighlightCallout` instance 2.
- **Google Search Console doc note:** GSC has no affiliate program and no `destinations` entry — it is still modeled as an `affiliate-links` doc (per Phase 46's schema, `destinations` is an array, not required to be non-empty) purely so `noCommissionPick` can be a relationship like everything else; its card variant never renders a CTA button at all (not even the neutral "no program yet" chip — that chip implies a *pending* program, GSC has none by design and never will). Render its reference row with a plain, non-accent, non-`rel=sponsored` link to `search.google.com/search-console` instead.

### `ToolCard` (`src/components/ToolCard.tsx`)
Single `Card`/`CardContent` shell (`p-8`, mirrors `AuthorCard`/`ServiceScopeCard`'s `p-8` override on the base `Card` — the base `p-6` default is for denser cards like `WebsiteCard`, not text-heavy ones):
```
Card > CardContent (p-8)

  p.text-label.uppercase.tracking-wide.opacity-70 (row label) + Prose (narrative)  — "Cómo lo uso"

  p.text-label... + p.text-body            — "Lo no tan bueno" (con, or honest-empty copy)
  p.text-label... + Link (accent, underline, per Prose link treatment)  — "Dónde lo usé"

```
This is the same "stacked label/value rows in one Card" shape as `ServiceScopeCardComponent` — deliberately reused because that block's own doc-comment already states the rule this page must also follow: it must read as one sheet of honest notes, never as a pricing/comparison grid.

### `AffiliateDisclosure` visual wrapper
`AffiliateDisclosure.tsx` itself stays untouched (its contract is legal copy + `hasAmazonLinks`
prop, not layout — Phase 46 built it that way on purpose). This phase adds the FIRST real frame
around it, used identically on `/stack` and inside post detail pages:
```
div.rounded-lg.border.border-border.bg-muted.p-4  (role="note")
  <AffiliateDisclosure hasAmazonLinks locale={locale} />   — text-label text-muted-foreground
```
`role="note"` (not `role="alert"` — this is persistent informational content, not a live-region
announcement) with a bordered, tinted (`bg-muted`) surface: legible and clearly a distinct block on
the page (FTC "clear and conspicuous" bar), without spending any accent color on a legal notice —
accent stays reserved for the CTA/no-commission-pick list above.

**Mount point on `/stack`:** immediately after the page `intro` paragraph, before the first
`categoryGroups` heading — i.e. before the first `ToolCard` (and therefore before the first
`AffiliateLink`) in DOM order. `hasAmazonLinks` is always `true` on `/stack` (the Gear section is
always present).

**Mount point on post detail pages:** immediately after the post header/byline
(`AuthorByline`/hero block), before the rendered `<RichText>` body — this is the DOM-order guarantee
INL-02 requires: source order, not scroll position, so it holds regardless of where in the article
the inline block actually sits. `hasAmazonLinks` here is computed by the pure editor-state scan
(INL-02) checking whether any node in `post.content` has `blockType === 'affiliate-inline'` whose
resolved `affiliate-links` doc has `program === 'amazon'`; if the post has the inline block at all
(any program) but zero Amazon ones, render the disclosure with `hasAmazonLinks={false}`.

on every post and case study, and a stack link there would appear on 100+ pages sitewide, diluting
exactly the service-page link equity STACK-05 is protecting. Add a single plain accent link
("Ver mi stack de herramientas" / "See my tool stack") inside `/authors/[slug]/page.tsx` itself
(the full profile page body, not the reusable card), styled `text-primary-text underline
underline-offset-2` — the same treatment `/websites/[slug]/page.tsx` already uses for its
"View related case study" link.

### Breadcrumbs / canonical — constraint clarification
STACK-01's "sin tocar `sitemap-data.ts`, `canonical.ts` ni `breadcrumbs.ts`" forbids **editing**
those files (no new `Section` union member, no new `buildStackTrail()` wrapper). It does not forbid
**calling** the generic functions those files already export. `/stack`'s `PageHero` trail is a
literal inline array built in the page/block component itself
(`[{ label: t.home, url: '/' }, { label: t.stackTitle }]`), passed straight to `PageHero`'s existing
`trail` prop and to the existing generic `buildBreadcrumbJsonLd(trail)` — both already accept a
plain `BreadcrumbItem[]`, so no shared file changes. `PageHero variant="index"` (not `detail`) is
correct here: `/stack` is a listing-style page (it presents many tools), not a single-entity detail
page.
