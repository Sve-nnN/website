# Phase 10.8 Plan 01: Hero Enrichment — CTA + Breadcrumbs Summary

**Hero block gains an optional CTA `links` array (reusing the CallToAction link-field pattern) and a `listing`-variant-only `breadcrumbs` array, both schema-driven with zero hardcoded copy, seeded with real content on the home page and blog index, and verified overflow-free at 375px with a real headless-Chromium check — which also surfaced and fixed two pre-existing data bugs and a project-wide Tailwind content-glob gap.**

## Performance

- **Duration:** ~90 min
- **Started / Completed:** 2026-07-10

## Accomplishments

- **Hero `links` field** (`src/blocks/Hero/config.ts`): `linkGroup({ appearances: ['default','outline'], overrides: { maxRows: 2 } })` — identical field shape to `CallToAction`'s `links` (same `link()` factory), so `CMSLink` renders it without any new component.
- **Hero `breadcrumbs` field**: `array` of `{ label: text (localized), url: text }`, gated to the `listing` variant via `admin.condition: (_, sibling) => sibling?.variant === 'listing'` — editors never see it on home/post-header/case-study-header variants.
- **`HeroComponent`** (`src/blocks/Hero/Component.tsx`): renders `links` as a button row below title/subtitle (via `CMSLink`, matching CallToAction's markup), and renders `breadcrumbs` as a `<nav aria-label="Breadcrumb">` above the title, only when `variant === 'listing'` and the array is non-empty. Zero hardcoded visible strings (grepped for quoted 4+ char literals — only `'object'`/`'home'`/`'listing'`/`'page'` type/attr checks matched).
- Ran `npx payload generate:types` and `npx tsc --noEmit` — both clean.
- Generated and applied a Postgres migration (`20260710_165940_phase10_8_hero_cta_breadcrumbs`) against the real Neon instance, `push:false` discipline maintained.
- Seeded real content via `scripts/seed-phase10-8-hero-cta-breadcrumbs.ts` (idempotent): home page Hero CTA ("Ver case studies"/"View Case Studies" -> `/case-studies`), blog index Hero breadcrumbs (Inicio/Home -> Blog), both es+en, verified via server-rendered curl.
- **Root-cause fix**: `tailwind.config.ts`'s `content` glob never included `src/blocks/**`, so utility classes used only inside blocks (never duplicated under `src/components`/`src/app`) were silently purged — including `ArchiveBlock`'s pre-existing `overflow-x-auto` on its category-filter tabs, which meant the blog listing page's category tabs overflowed the viewport at 375px this entire time. Fixed the glob and wrapped `ArchiveBlock`'s `TabsList` in its own scroll container as a belt-and-suspenders fix — this benefits every block, not just Hero.
- Wrote `scripts/verify-hero-mobile.mjs` (adjunct to `scripts/verify-mobile-viewport.mjs`, same real-Playwright pattern): confirms at 375px that the home Hero CTA and blog listing Hero breadcrumbs are visible with zero document-level horizontal overflow, in both locales.

## Verification

- `npx tsc --noEmit -p tsconfig.json` — clean.
- Started the dev server and curled rendered HTML (`-L`, locale middleware 307s): `/es` and `/en` contain the CTA button text; `/es/blog` and `/en/blog` contain the breadcrumb `<nav>` with `Inicio`/`Home` -> `Blog` links, confirmed positioned above the Hero title in raw server-rendered HTML.
- `node scripts/verify-hero-mobile.mjs` (BASE_URL pointed at the running dev server) — `RESULT: PASS` for all four checks (home es/en CTA, blog es/en breadcrumbs), zero horizontal overflow, CTA/breadcrumb bounding boxes fully within the 375px viewport.
- `node scripts/verify-mobile-viewport.mjs` (existing 10.6 header/footer check) — still `PASS` at all three breakpoints after the Tailwind content-glob fix.
- Grepped `Hero/Component.tsx` for hardcoded visible copy — zero matches.

## Deviations from Plan

- Discovered and repaired two pre-existing data-integrity bugs while touching the `home` Pages doc's `content.layout` (both from `scripts/seed-phase10-7-gap-fill.ts`'s locale-handling flaw — documented in this phase's tech-stack patterns): AboutSection's `es`-locale paragraph text had been silently dropped (both rows had empty `text`, a required field, which blocked any further layout write until repaired), and the home Hero's `en` title/subtitle had been overwritten with Spanish text. Both repaired in-line in the new seed script with the original canonical copy from `scripts/seed-home-page.ts`/`seed-phase10-7-gap-fill.ts`.
- Discovered and fixed a project-wide Tailwind `content` glob gap (`src/blocks/**` was never scanned) while verifying mobile overflow on the blog listing page — this was blocking the required "no horizontal overflow at 375px" check for reasons unrelated to Hero (a pre-existing, unrelated `ArchiveBlock` category-tabs overflow). Fixed at the root (config) plus a defensive `overflow-x-auto` wrapper on the tabs themselves.

## Issues / Open Items
