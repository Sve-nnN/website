`scripts/seed-phase19-service-pages.ts` / `seed-phase20-geo-pages.ts` lexical + id-reuse helpers (duplicate these verbatim into the new script, self-contained, no cross-script import, per established convention):

```typescript
function lexicalParagraph(text: string): LexicalRoot
function lexicalWithHeading(heading: string, paragraphs: string[]): LexicalRoot
function reapplyIds(freshLayout, referenceLayout): Record<string, unknown>[]
```

`reapplyIds` walks `freshLayout` by index and copies `id` (+ `columns[]`/`faqs[]`/`links[]` sub-ids) from the same-index block in `referenceLayout` ONLY when `blockType` matches at that index; mismatches are logged and skipped (fresh id generated), never force-attached to unrelated content.

**Critical deviation from the Phase 19/20 `upsertPage` pattern (read this before writing Task 3):** In Phase 19/20, `upsertPage` fetches `referenceLayout` ONCE before the locale loop, which is safe there because either (a) the doc is brand-new (`create` with 'es' establishes the reference doc in the exact shape 'en' will also write), or (b) re-running the idempotent script against an already-restructured doc (same shape both locales). Here the existing 8 docs are being restructured from the OLD 4-block Phase-19 shape to a NEW 10-block shape on the FIRST run — the OLD saved layout will NOT block-type-match the NEW layout at most indices, so if `referenceLayout` is fetched only once before the loop, the 'es' and 'en' writes in this same run would each independently generate fresh ids for the mismatched blocks (breaking cross-locale id consistency for this run — the exact bug class behind the 05-12/13-02/15-02 pattern and Phase 19's CR-01 incident). **Fix: for each service doc, after writing the 'es' locale, re-fetch the doc's current layout via `findByID` and use THAT as the reference for the 'en' write** (i.e. refetch inside the per-locale loop, not once before it) — so 'en' always reapplies ids from the 'es' layout this same run just wrote, which is shape-identical. On idempotent re-runs the same refetch-per-locale approach still works correctly (each write refreshes the reference for the next one).
