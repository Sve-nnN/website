# Phase 12 — UI Design Contract

> Visual and interaction contract for the 3 new author-page sections (Expertise, Educación y Certificaciones, Experiencia). Generated by gsd-ui-researcher using `ui-ux-pro-max`, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (already initialized — `components.json` present since Phase 1) |
| Preset | `style: new-york`, `baseColor: neutral`, `cssVariables: true`, no prefix |
| Component library | Radix primitives via shadcn (`Card`, `Badge`, `Avatar` already installed under `src/components/ui/`) |
| Icon library | lucide-react only — no brand icon packs (matches `socialIconMap` pattern in `AuthorCard.tsx`) |
| Font | `font-heading` = Khand (var `--font-khand`), body = Geist Sans (var `--font-geist-sans`) — both already wired in `tailwind.config.ts`, no new fonts for this phase |

No new shadcn components are pulled for this phase. `Card` and `Badge` are reused as-is from `src/components/ui/`. The Experience timeline is hand-built with `div`/`ol`/`li` + existing tokens (no timeline primitive exists in shadcn — this is expected and matches the `ui-ux-pro-max` recommendation to compose custom layout on top of token-driven primitives rather than pull an unvetted third-party block).

`ui-ux-pro-max --design-system "professional portfolio consultant timeline"` confirms the codebase's already-locked direction (Minimalism/Swiss style, monochrome + single accent, 150–300ms hover transitions, WCAG AA/AAA target) — no palette or type-system change is recommended or needed; this phase composes strictly on Phase 7/8 tokens.

## Spacing Scale

Declared values (must be multiples of 4) — inherited from Phase 7/8, no new scale introduced:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps inside timeline items |
| sm | 8px | Badge gap in Expertise tag cloud (`gap-2`), compact spacing |
| md | 16px | Card internal padding fallback, gap between education-card fields |
| lg | 24px | Education grid gap (`gap-6`), Card padding (`p-6`) |
| xl | 32px | Timeline connector left offset (`pl-8`) |
| 2xl | 48px | Spacing between the 3 new sections and existing sections (`mt-12`) — same value already used for the Posts/Case Studies section breaks in this page |
| 3xl | 64px | Page-level `py-16` on the outer `Container` (unchanged, pre-existing) |

Exceptions: none. Timeline dots are decorative (`size-3.5`/14px), not touch targets — no 44px exception applies since nothing in these 3 sections is interactive/clickable (Expertise badges, education cards, and timeline items are all static display, matching the "informational sections" nature of this phase).

Section order (Claude's Discretion per CONTEXT.md, locked here): **Expertise → Educación y Certificaciones → Experiencia**, each wrapped exactly like the existing `Posts`/`CaseStudies` sections in `page.tsx` (`<section className="mt-12">`), placed after `<AuthorCard>` and before the `posts`/`caseStudies` grids — logical E-E-A-T order (what he knows → how he's credentialed → what he's done).

## Section Specs

### 1. Expertise (Badge tag cloud)

Reuses the exact pattern already in `AuthorCard.tsx` for `credentials`:

```tsx
<section className="mt-12">
  <h2 className="font-heading text-heading mb-6">{t.expertise}</h2>
  <div className="flex flex-wrap gap-2">
    {doc.expertise.map((item, i) => (
      <Badge key={i} variant="secondary">{item.topic}</Badge>
    ))}
  </div>
</section>
```

- Renders only if `expertise.length > 0` (same conditional-render contract as `posts`/`caseStudies` — no empty state UI, section is simply omitted, matches success criteria #6's "placeholder claramente editable desde /admin" being satisfied at the admin-field level, not by rendering an empty section publicly).
- Section heading copy: ES "Expertise" / EN "Expertise" (accepted loanword already used this way in this project's SEO/tech content register — no translation needed, avoids an awkward literal translation like "Pericia").
- 4 real items from CONTEXT.md `<specifics>` (ES) — EN translations to be authored during planning per CONTEXT.md's "Claude's Discretion" (professional, matches `jobTitle`/`bio` EN tone already established).

### 2. Educación y Certificaciones (2-column card grid)

```tsx
<section className="mt-12">
  <h2 className="font-heading text-heading mb-6">{t.education}</h2>
  <div className="grid grid-cols-1 md:grid-cols-2 gap-6">
    {doc.education.map((item, i) => (
      <Card key={i} className="flex gap-4 p-6">
        <div className="flex size-12 shrink-0 items-center justify-center rounded-md bg-muted">
          {logo?.url ? (
            <Image src={logo.url} alt={logo.alt ?? item.institution} width={48} height={48} className="rounded-md object-contain" />
          ) : (
            <GraduationCap className="size-6 text-muted-foreground" />
          )}
        </div>
        <div>
          <p className="font-heading text-body font-semibold">{item.degree}</p>
          <p className="text-body text-muted-foreground">{item.institution}</p>
          <p className="mt-1 text-label text-muted-foreground">{dateRange}</p>
        </div>
      </Card>
    ))}
  </div>
</section>
```

- Grid: `grid-cols-1 md:grid-cols-2 gap-6` — exact breakpoint locked in CONTEXT.md, mobile-first (single column ≤767px, 2 columns ≥768px). Verify no overflow/cramping at 375px (single column, full card width) and at 768px (2 columns, each ~350px wide with real ES copy — degree strings like "Ingeniero de software" must not wrap awkwardly against the logo box).
- Logo box uses `rounded-md` (not `rounded-full` like `Avatar`) — institutional logos are typically rectangular, `size-12` (48px) matches a secondary hierarchy level below the `AuthorCard` avatar's `size-16`.
- Fallback icon when `education[].logo` is empty (expected for both real items per CONTEXT.md — no logo assets confirmed available): `GraduationCap` from lucide-react, `size-6`, `text-muted-foreground`, centered in a `bg-muted` box — same fallback treatment pattern as `Avatar`'s `AvatarFallback`.
- Date range format: `Intl.DateTimeFormat(locale, { month: 'short', year: 'numeric' })` per start/end, joined with an en dash: e.g. ES "may 2022 – ago 2028", EN "May 2022 – Aug 2028". If `endDate` is null/absent, render "Presente" (ES) / "Present" (EN) instead of a blank — this is a UI contract even though neither of the 2 real education items currently has a null end date, so future admin-entered rows degrade gracefully.
- Renders only if `education.length > 0` (same omit-if-empty contract as above).
- Section heading copy: ES "Educación y Certificaciones" / EN "Education & Certifications".

### 3. Experiencia (visual timeline — the new pattern)

The one genuinely new visual pattern in this phase. `ui-ux-pro-max`'s design-system pass for this product type reinforces the codebase's existing minimalism direction (monochrome neutrals + single accent, subtle 150–300ms transitions) — the timeline should read as a quiet, single-accent-dot rail, not a decorative/colorful Gantt-style chart.

```tsx
<section className="mt-12">
  <h2 className="font-heading text-heading mb-6">{t.experience}</h2>
  <div className="relative pl-8">
    <div aria-hidden className="absolute left-[7px] top-1 bottom-1 w-px bg-border" />
    <ol className="space-y-8">
      {doc.experience.map((item, i) => (
        <li key={i} className="relative">
          <span
            aria-hidden
            className="absolute -left-8 top-1 size-3.5 rounded-full border-2 border-background bg-primary"
          />
          <p className="text-label text-muted-foreground">{dateRange}</p>
          <h3 className="font-heading text-body font-semibold">{item.role}</h3>
          <p className="text-body text-muted-foreground">{item.company}</p>
          {item.description && (
            <p className="mt-2 text-body text-muted-foreground">{item.description}</p>
          )}
        </li>
      ))}
    </ol>
  </div>
</section>
```

- Structure: one continuous vertical connector line (`bg-border`, 1px, `.dark`-safe since `--border` has an explicit dark value) behind a column of dots (`bg-primary`, the ONLY accent usage in this section) + text content indented to the right of the rail.
- Single-column left-rail layout at ALL breakpoints (375/768/1280) — no alternating left/right desktop layout. This is a deliberate simplicity choice: the reference site's flat `<ul>` only had 2 items, and an alternating-side timeline adds layout complexity/bug surface for zero benefit at this content volume. If `experience[]` grows significantly in a future phase, revisit.
- Dot/line alignment (`left-[7px]` on the line, `-left-8` on each dot) is a starting recipe, not a pixel-perfect mandate — the executor MUST visually verify the dot is centered on the line at 375/768/1280px and adjust the offset by a few px if the rendered `size-3.5` dot doesn't sit dead-center; this is expected implementation tolerance, not a spec violation.
- Order: render items in the order they exist in `experience[]` (already reverse-chronological in the real CONTEXT.md data — do not re-sort).
- Renders only if `experience.length > 0` (same omit-if-empty contract).
- Section heading copy: ES "Experiencia" / EN "Experience".
- Motion: no entrance animation on this timeline (server-rendered, no client JS needed) — matches the project's existing pattern of RSC-only author-page rendering. If a future phase adds scroll-reveal, it must respect `prefers-reduced-motion` per the global safety net already in `globals.css`.
