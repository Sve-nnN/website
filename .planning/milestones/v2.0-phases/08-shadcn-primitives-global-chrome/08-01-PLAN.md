<!-- Phase 7 token layer this plan consumes directly. Already live in the repo — no further wiring needed, only className usage. -->

From `tailwind.config.ts` `theme.extend`:
```
boxShadow: { sm: 'var(--shadow-sm)', md: 'var(--shadow-md)', lg: 'var(--shadow-lg)', focus: 'var(--shadow-focus)' }
transitionDuration: { fast: 'var(--motion-fast)', base: 'var(--motion-base)', slow: 'var(--motion-slow)' } // 150/250/400ms
transitionTimingFunction: { out: 'var(--ease-out)', standard: 'var(--ease-standard)' }
```

Usable Tailwind utility classes: `shadow-sm` `shadow-md` `shadow-lg` `shadow-focus` · `duration-fast` `duration-base` `duration-slow` · `ease-out` `ease-standard`.

Important gotcha confirmed by direct inspection: because `theme.extend.boxShadow` only defines the keys `sm`/`md`/`lg`/`focus` (no `DEFAULT`), Tailwind's *bare* `shadow` class still resolves to Tailwind's stock default shadow, NOT `--shadow-md`. Every current primitive using bare `shadow` (button default/destructive variant, card, badge default/destructive, navigation-menu viewport) is the actual gap this plan closes — replace bare `shadow`/`shadow-sm`/`shadow-md` occurrences with an explicit, elevation-appropriate named token (`shadow-sm` for resting/low elevation, `shadow-md` for popovers/raised cards, `shadow-lg` for the sheet overlay, `shadow-focus` for focus-visible rings).

The global `prefers-reduced-motion` rule in `globals.css` already neutralizes all `transition-duration`/`animation-duration` site-wide — any `active:scale-*` or `duration-*` class added here is automatically safe, no extra guard needed in component code.
