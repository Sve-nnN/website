# Phase 16 — UI Design Contract

> Visual and interaction contract for the Hero home background shader. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This phase changes exactly one visual surface — the `variant: 'home'` Hero's background, from solid `bg-secondary` to an animated WebGL grainy gradient. Title, subtitle, CTAs, and breadcrumbs are explicitly unchanged (locked in CONTEXT.md). This contract is intentionally narrow: spacing, typography, and copywriting sections below confirm "no change" rather than introduce new values.

## Color

The shader must be built exclusively from colors already declared in `src/app/globals.css` (Phase 7 tokens) — no new hex values invented, per CONTEXT.md. The Hero `home` background is dark-surface in both themes (`--secondary`), so the shader replaces that dark navy field with a navy→navy-tint→ember gradient, keeping `--secondary-foreground` (off-white) text readable on top.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%, `colorBack` + primary gradient stop) | Light: `#12141C` (`--secondary`) · Dark: `#23283A` (`--secondary`) | Base/back color of the `GrainGradient` — matches the current solid Hero background so the shader reads as an evolution, not a jarring swap |
| Secondary tonal stop (30%) | Light: `#23283A` (dark theme's `--secondary`, reused as a navy tint for depth) · Dark: `#3A4159` (`--chart-3`, already an existing navy tint) | Mid gradient stop — adds depth/movement without introducing a new hue; both values are lifted verbatim from existing token declarations elsewhere in `globals.css` |
| Accent (10%, minority gradient stop) | Light: `#F7581E` (`--primary`) · Dark: `#FF7A45` (`--primary`) | Ember stop — reserved exclusively for the smallest gradient weighting; must read as a warm highlight moving through the navy field, never dominate the composition |
| Destructive | `#DC2626` (light) / `#F87171` (dark) — `--destructive` | Not used in this phase (no destructive actions in the Hero) |

Accent reserved for: the ember gradient stop inside `GrainGradient`'s `colors` array only. Do not apply ember to text, borders, or any other Hero element beyond what already exists (CTAs already use `--primary` via the existing `CMSLink`/button styling — unchanged).

Text-on-shader contrast: `--secondary-foreground` (`#FAFAF7`) must remain the title/subtitle/breadcrumb color, unchanged. Because the gradient's dominant and mid stops stay within the existing dark-navy family (never lighter than `#23283A`) and the ember stop is capped at low `intensity`/minority weighting, contrast against off-white text stays at or above the already-verified `--secondary`/`--secondary-foreground` pairing from Phase 11. Executor must visually confirm (screenshot, both themes) that no gradient frame washes out enough to threaten WCAG AA on the title.

## Shader Parameters (`GrainGradient`, `@paper-design/shaders-react`)

Verified against the component's real API (shaders.paper.design docs) rather than assumed. Values below target "subtle, slow, professional B2B" per CONTEXT.md.

| Prop | Value | Rationale |
|------|-------|-----------|
| `colors` | Light: `["#12141C", "#23283A", "#F7581E"]` · Dark: `["#23283A", "#3A4159", "#FF7A45"]` | 3 stops, ember as minority color (see Color section) |
| `colorBack` | Light: `#12141C` · Dark: `#23283A` | Matches current solid `--secondary` so the base tone doesn't shift |
| `shape` | `"wave"` | Calmest of the 7 available shapes (`wave`/`dots`/`truchet`/`corners`/`ripple`/`blob`/`sphere`); avoids the more novelty-feeling forms (`blob`, `sphere`, `truchet`) that read as experimental rather than B2B |
| `softness` | `0.8` | Smooth color transitions, no hard edges (range 0–1) |
| `intensity` | `0.25` | Low distortion between color bands — subtle, not busy (range 0–1) |
| `noise` | `0.12` | Subtle grain overlay, present but not gritty (range 0–1) |
| `speed` | `0.3` (live) / `0` (reduced motion) | Slow, ambient movement; `speed=0` fully stops the animation loop per the component's own API — this is the mechanism for `prefers-reduced-motion` handling, no separate CSS fallback needed |
| `scale` | `1` | Default — no need to zoom/distort the gradient field for this use case |
| `fit` | `"cover"` | Fills the Hero section edge-to-edge regardless of aspect ratio |
| `width` / `height` | `"100%"` / `"100%"` | Fill parent container (`absolute inset-0` wrapper, matching the pattern the existing `Image` fallback already uses in `Component.tsx`) |

**Reduced motion implementation contract:**
- Client Component reads `window.matchMedia('(prefers-reduced-motion: reduce)').matches` on mount (plus a `change` listener, since the media query can flip without a reload).
- When reduced motion is preferred, pass `speed={0}` (and a fixed `frame` value, e.g. `0`) to `GrainGradient` — this freezes it on a single static frame of the same gradient, satisfying HERO-ANIM-04 without a second code path or a CSS-only fallback gradient.
- This logic must live entirely inside the new Client Component; `Component.tsx` (Server Component) passes no motion-related props.

**Component boundary:**
- New file: `src/components/HeroGrainGradient.tsx` (`'use client'`), rendering `<GrainGradient>` sized to fill its parent via an `absolute inset-0` wrapper — same positioning pattern the current `Image` background fallback uses.
- `src/blocks/Hero/Component.tsx` stays a Server Component. Its `isHome` branch swaps the current `bg-secondary` solid class + optional `<Image>` overlay for `<HeroGrainGradient />` rendered behind the existing `<Container>` content (z-index unchanged: shader at the back, `Container` stays `relative z-10`).
- The `media` field in the Hero schema is NOT removed — it stays available for other variants, simply unused/covered on `variant: 'home'`, per CONTEXT.md.
