# Phase 39 — UI Design Contract

> **Governing rule (from 39-CONTEXT.md and CLAUDE.md):** this phase EXTENDS existing CaseStudies frontend patterns byte-for-byte. No new design language, no new tokens, no new component variants. Every value below is copied from the codebase's already-implemented design system (`src/app/globals.css`, `tailwind.config.ts`) and the existing `CaseStudyCard` / `FeaturedCaseStudiesBlock` / `ArchiveBlock` / `/case-studies` routes — not re-derived.

## Spacing Scale

Declared values (multiples of 4 only) — identical to the project-wide scale already locked in `tailwind.config.ts` comments and used by every CaseStudies surface. No exceptions or new values for this phase.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge/tag inline padding (stack tags on WebsiteCard/detail) |
| sm | 8px | Compact spacing (KPI/lighthouse-score card internal gaps, mirrors CaseStudy KPI cards) |
| md | 16px | Default element spacing, `Card`/`CardContent` padding (`p-6` = 24px is the existing Card default — kept as-is, do not change) |
| lg | 24px | Grid gutters (`gap-6` on the 3-col card grid, same as CaseStudies listing/ArchiveBlock) |
| xl | 32px | Layout gaps between page sections |
| 2xl | 48px | Major section breaks (hero → lighthouse scores → highlights → challenges → screenshots) |
| 3xl | 64px | Page-level top/bottom padding (`Container className="py-16"` on listing, mirrors `/case-studies`) |

Exceptions: none. Grid: `grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 gap-6` — copied verbatim from `ArchiveBlock`/`FeaturedCaseStudiesBlock`/`/case-studies` listing, do not invent a different breakpoint set.

## Typography

Identical to the project-wide 4-size/2-weight budget already implemented in `tailwind.config.ts`. No new size or weight is introduced for Websites.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (`text-body`) | 400 (Inter Regular) | 1.5 |
| Label | 14px (`text-label`) | 600 (Inter Semibold) | 1.4 |
| Heading | clamps 22px→28px (`text-heading`, `font-heading`/Khand) | 600 | 1.2 |
| Display | clamps 36px→56px (`text-display`, `font-display`/Array) | 600 | 1.05 |

Mapping onto Websites content (mirrors CaseStudyCard/detail exactly):
- `WebsiteCard` client label → `text-label text-muted-foreground`
- `WebsiteCard` title → `font-heading text-heading`
- `WebsiteCard` industry/role subtitle → `text-body text-muted-foreground`
- `WebsiteCard` hero metric (top Lighthouse performance score, e.g. "98 Performance") → `font-heading text-heading font-semibold text-primary-text` — same treatment as `caseStudy.heroMetric`
- Detail page `<h1>` title → `font-display text-display`
- Detail page section headings ("Highlights"/"Destacados", "Challenges"/"Retos", "Stack", "Screenshots"/"Capturas", "Lighthouse") → `font-heading text-heading`

## Component Contract Detail (traceability for planner/executor)

### `WebsiteCard` (`src/components/WebsiteCard.tsx`)
Structural clone of `CaseStudyCard` — same `<Link><Card><CardContent>` shape, same class names, only field mapping changes:

| CaseStudyCard | WebsiteCard equivalent |
|---|---|
| `href={/case-studies/${slug}}` | `href={/websites/${slug}}` |
| `client.name` label | `client.name` label (same `clientes` relationship) |
| `title` heading | `title` heading |
| `sector` subtitle | `industry` subtitle |
| `heroMetric` (accent, bold) | `lighthouse.performance` formatted as `"{n} Performance"` (accent, bold) — falls back to hiding the line entirely if `lighthouse.performance` is null/undefined, exactly as `CaseStudyCard` hides `heroMetric` when absent |

Used in exactly 3 places, identical to `CaseStudyCard`'s usage surface: `FeaturedWebsitesBlock`, `ArchiveBlock` (when `relationTo: 'websites'`), and the `/websites` listing page.

### `FeaturedWebsitesBlock`
- `config.ts`: block slug `featuredWebsitesBlock`, fields `title` (localized text) + `limit` (number, default 3, min 1, max 6) — byte-for-byte field shape clone of `FeaturedCaseStudiesBlock`.
- `Component.tsx`: reads `featuredContent.featuredWebsites` (new relationship field on the `FeaturedContent` global, `hasMany: true`, `relationTo: 'websites'` — same shape as `featuredCaseStudies`), renders `<Container className="py-12">` + optional `<h2>` + the same 3-col grid mapping `WebsiteCard`.
- Register in `blockComponents` registry (`src/blocks/blockRegistry.ts` or equivalent) alongside `featuredCaseStudiesBlock`.

### `ArchiveBlock` extension
- `config.ts`: add `{ label: 'Websites', value: 'websites' }` to the `relationTo` select's `options`; add `'websites'` to `selectedDocs.relationTo` array.
- `Component.tsx`: broaden the `docs` union type to `(Post | CaseStudy | Website)[]`; add a third branch in the render map — `relationTo === 'posts' ? <PostCard .../> : relationTo === 'websites' ? <WebsiteCard websiteData={...} /> : <CaseStudyCard .../>`. Category filter tabs remain posts-only (`enableCategoryFilter` condition unchanged) — websites, like case-studies, get no category filter UI.
- `ScrollReveal` wrapper and `isAboveFold` priority logic (first 3 items) carry over unchanged.

### Routes
- `/[locale]/websites/page.tsx`: byte-for-byte structural clone of `/[locale]/case-studies/page.tsx` — `payload.find({ collection: 'websites', locale, limit: 50 })`, `buildWebsitesTrail(locale)`, same breadcrumb `<nav>` markup, same empty-state block (copy per table above), same 3-col grid of `WebsiteCard`, same trailing `<JsonLd data={buildBreadcrumbJsonLd(trail)} />`.
- `/[locale]/websites/[slug]/page.tsx`: structural clone of `/[locale]/case-studies/[slug]/page.tsx` with this field mapping:

| CaseStudy detail section | Website detail equivalent |
|---|---|
| Hero: client/sector/period chips, title, heroSubtitle, heroMetric | Hero: `client.name`/`industry`/`year` chips, `title`, `role` as subtitle, no single heroMetric — hero stays text-only (no `heroImage` field exists on `Websites`, so the `aspect-[21/9]` image band from CaseStudy hero is dropped, not faked) |
| KPI grid (4 `doc.kpis`) | Lighthouse score grid (4 fixed cards: Performance/Accessibility/Best Practices/SEO from `doc.lighthouse.*`) — same `grid-cols-2 md:grid-cols-4 gap-6` + `rounded-lg bg-secondary text-secondary-foreground p-6 text-center` card treatment, same `text-display font-display font-semibold text-primary` number styling |
| "El cliente" / clientContext richtext | Not applicable — Websites has no clientContext field, section omitted |
| "El reto" / challenge bullet list | "Challenges" / `doc.challenges[].text` bullet list — identical `<ul className="list-disc pl-6 space-y-2 text-body">` |
| "La solución" / numbered steps | Not applicable — Websites has no solution field, section omitted |
| Results chart + before/after metrics | Not applicable — Websites has no results field, section omitted |
| n/a | New: "Highlights" / `doc.highlights[].text` bullet list, same list styling as Challenges |
| n/a | New: "Tech Stack" / `doc.stack[].tag` rendered as `Badge` chips in a `flex flex-wrap gap-2` row |
| n/a | New: "Screenshots" / `doc.screenshots[].image` rendered as a responsive image grid (`grid-cols-1 sm:grid-cols-2 gap-4`, `next/image` with `sizes` per existing image patterns in the codebase) |
| Author byline | Not applicable — Websites has no author field, section omitted |
| n/a | New (optional, only if `relatedCaseStudy` populated): "View related case study" link to `/case-studies/{relatedCaseStudy.slug}`, styled as an in-body accent link |
| `creativeWorkData` JSON-LD: `@type: 'CreativeWork'` | `@type: 'CreativeWork'` (NOT `SoftwareApplication` — explicit success-criterion #5), `name: doc.title`, `about: doc.role ?? doc.industry` |
| `buildCaseStudiesTrail` | `buildWebsitesTrail` — new wrapper in `breadcrumbs.ts` |

Sections present on CaseStudy but absent on Website (`clientContext`, `solution`, `results`, `author`) are simply omitted from the Website detail template — never rendered as empty/placeholder blocks. Sections unique to Website (`highlights`, `stack`, `screenshots`, `lighthouse`, `relatedCaseStudy`) are new but reuse existing typographic/spacing/color treatments already cataloged above; none introduce new visual primitives.

### Breadcrumbs (`src/lib/breadcrumbs.ts`)
Add `'websites'` to the `Section` union, `SECTION_LABELS` (`{ es: 'Sitios web', en: 'Websites' }`), and `SECTION_SEGMENTS` (`{ es: 'websites', en: 'websites' }` — English segment kept in both locales, same precedent as `'case-studies'`, which the file's own comment confirms is NOT locale-prefixed). Export `buildWebsitesTrail(locale, current?)` as a thin wrapper calling `buildSectionTrail(locale, 'websites', current)`, matching `buildCaseStudiesTrail`'s exact signature and doc-comment style.

### Sitemap (`src/lib/sitemap-data.ts`)
Add a `{ collection: 'websites', prefix: 'websites', hasDrafts: true, group: 'websites' }` entry to `SITEMAP_COLLECTIONS`; add `'websites'` to the `SitemapEntry['group']` union and `SITEMAP_GROUP_LABELS` (`{ websites: 'Websites' }`). No special-case URL branching needed (unlike the Services `pages` exception) — `/websites` and `/websites/{slug}` follow the generic `prefix/slug` path already handled by the existing loop.
