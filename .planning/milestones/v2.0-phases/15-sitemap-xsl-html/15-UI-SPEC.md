## Surface 1 — `public/sitemap.xsl`

Static XSL stylesheet transforming `sitemap.xml` into a readable table when opened directly in a browser. Pure XSLT 1.0 + inline `<style>` block. No JS, no external stylesheet, no design tokens (XSL is served standalone from `/public`, outside the Next.js CSS pipeline).

**Structure:**
- Page title: "Sitemap — {siteName}" (h1)
- One `<table>` with columns: **URL** | **Last Modified** | **Language**
- One row per `<url>` entry in the XML, sorted in document order (no re-sorting needed — the route handler already emits them grouped)
- URL column renders as a real clickable `<a href="{loc}">` (so the XSL output is itself navigable, not just a report)
- Language column reads the `hreflang` alternate(s) if present, else shows "—"
- Footer line: total URL count + link back to `/sitemap.html` for the grouped view

**Approximate palette (hardcoded hex, NOT CSS variables — XSL can't consume them):**

| Role | Value | Usage |
|------|-------|-------|
| Background | `#FAFAF7` | Page background (matches site's light-mode `--background`) |
| Text | `#12141C` | Body text (matches site's light-mode `--foreground`) |
| Accent | `#F7581E` | Table header background, link color (matches site's `--primary`) |
| Border | `#E5E5DE` | Table row dividers (approximation of light-mode `--border`, lightened for a plain table since XSL has no dark-mode media-query concept worth the complexity here) |
| Row stripe | `#F0F0EA` | Alternating row background for scan-ability |

No dark mode for the XSL file — this is a one-off diagnostic view most commonly opened by crawlers/devs, not an end-user surface; a single light theme is sufficient and keeps the file simple.

**Typography (system stack, no web fonts):**

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| H1 | 20px | bold (700) | 1.2 |
| Table header | 13px | bold (700) | 1.4 |
| Table cell | 14px | normal (400) | 1.5 |

Font stack: `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Helvetica, Arial, sans-serif`.

**Spacing:** 8px cell padding vertical, 12px horizontal. 24px page margin. 16px gap between H1 and table.

## Surface 2 — `sitemap.html` route (`src/app/sitemap-page` or equivalent route handler)

Real navigable HTML page, same content as the XML, grouped by section: **Pages / Blog / Case Studies / Authors / Categories**. Served via a route handler (not `page.tsx`) so the URL is the literal `/sitemap.html`, but the response can still be a full HTML document that inlines the app's real CSS custom properties — this is the one surface in this phase that CAN be token-aware.

**Structure:**
- Page title: "Sitemap" (h1)
- One `<section>` per group (Pages, Blog, Case Studies, Authors, Categories) — only render groups that have at least one entry
- Each section: `<h2>` group label + `<ul>` of links, each item showing the URL as link text and, where locale alternates exist, a small "EN · ES" language switcher inline
- Skip entries with zero URLs in a group entirely (no empty "Blog (0)" sections)
- Link back is not needed (this IS the landing page linked from the footer)

**Nice-to-have (not required):** inline the site's real light/dark CSS custom properties (`--background`, `--foreground`, `--primary`, `--border`, `--muted-foreground` from `globals.css`) plus a `prefers-color-scheme: dark` media query, so this page visually matches the app's actual theme instead of a hardcoded approximation. If implementation time doesn't allow, fall back to the same hardcoded light palette as the XSL file (see above) — legibility, not brand-matching, is the bar per CONTEXT.md.

**Typography (if reusing app fonts):** `var(--font-geist-sans)` for body/UI text; fallback to the same system stack as the XSL file if font variables aren't available in the route handler context.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| H1 | 28px | semibold (600) | 1.2 |
| H2 (group label) | 20px | semibold (600) | 1.2 |
| Link / list item | 16px | normal (400) | 1.5 |
| Language tag | 13px | normal (400) | 1.4 |

**Color (if using app tokens — nice-to-have):**

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` | Page background |
| Secondary (30%) | `--muted` / `--border` | Section dividers, subtle group backgrounds |
| Accent (10%) | `--primary` | Link color on hover/focus only |
| Text | `--foreground` / `--muted-foreground` | Body text / language tags |

Accent reserved for: link hover/focus state only. Do not apply accent color to headings, backgrounds, or borders.

**Spacing:** reuse the project's 8-point scale — 16px between list items, 32px between sections, 48px page top/bottom margin, max content width 720px centered (this is a text-dense utility page, not a full-bleed layout).

## Copywriting Contract

| Element | Copy |
|---------|------|
| XSL page title | "Sitemap — {siteName}" |
| XSL table headers | "URL" / "Last Modified" / "Language" |
| XSL footer line | "{N} URLs — view grouped list" (linking to `/sitemap.html`) |
| HTML page title | "Sitemap" |
| HTML group labels | "Pages" / "Blog" / "Case Studies" / "Authors" / "Categories" (localized to ES equivalents if the page itself is locale-aware; if the sitemap stays locale-neutral, English labels are acceptable since this is a utility/crawler-facing surface) |
| Empty state | Not applicable — groups with zero entries are omitted entirely, no empty-state copy needed |
| Error state | Not applicable — this route has no user input or failure mode beyond the underlying sitemap query, which already has error handling in `sitemap.ts` |
| Destructive actions | None — this phase has no destructive actions |
