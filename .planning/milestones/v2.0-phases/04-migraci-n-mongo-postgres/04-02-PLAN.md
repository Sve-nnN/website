<source_media_shape>
Cada doc en `media.json` (JuanPortfolio, Vercel Blob) tiene: `id` (ObjectId string), `alt`, `filename`, `url` (puede ser un path relativo local `/media/xxx` o una URL absoluta de Vercel Blob), `cloudinaryUrl` (algunos docs YA fueron subidos a Cloudinary manualmente en el sitio viejo — si existe, usarla como fuente de descarga preferente sobre `url`), `mimeType`, `filesize`, `dominantColor`.

Para descargar el binario real: si `doc.cloudinaryUrl` existe, usarla; si no, y `doc.url` empieza con `http`, usarla directo; si `doc.url` es un path relativo (`/media/...`), prefijarla con `https://juan-tech.com` (dominio real del sitio viejo) antes de hacer fetch — el server viejo sirve esos archivos por HTTP incluso si el registro Mongo no tiene URL absoluta.
</source_media_shape>

<target_local_api_upload>
El Local API de Payload acepta binarios así: `payload.create({ collection: 'media', data: { alt }, file: { data: buffer, mimetype, name, size } })` — este `file` es lo que dispara el hook `beforeChange`/`handleUpload` del `cloudinaryAdapter` ya wireado en `src/payload.config.ts` (gateado por `hasCloudinaryCreds`, ya en true en este entorno desde Fase 3). NO llamar a `cloudinaryService`/SDK de Cloudinary directamente desde este script — reusar exclusivamente el pipeline ya existente subiendo vía Local API.
</target_local_api_upload>
