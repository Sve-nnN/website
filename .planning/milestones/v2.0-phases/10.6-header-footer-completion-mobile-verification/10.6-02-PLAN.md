Diferencias clave para este plan (no asumir el mismo where que RelatedPosts):
- Para source 'latestPosts': collection 'posts', sort '-publishedAt', where { _status: { equals: 'published' } }, limit entry.limit ?? 5. Campos confirmados en src/collections/Posts/index.ts: publishedAt, title, y slugField('title') (produce slug).
- Para source 'latestCaseStudies': collection 'case-studies', sort '-createdAt' (esta coleccion NO tiene publishedAt, confirmado por lectura directa del schema), where { _status: { equals: 'published' } }, limit entry.limit ?? 5. Campos confirmados en src/collections/CaseStudies/index.ts: title, slugField() (produce slug).
- Ambas colecciones tienen versions.drafts habilitado, por lo que _status (draft|published) es un campo valido para where.
- El filtro _status es OBLIGATORIO: el Local API por defecto usa overrideAccess true y NO respeta el access control authenticatedOrPublished de las colecciones, asi que sin este where explicito el footer (visible en TODAS las paginas del sitio) podria filtrar borradores a usuarios anonimos.

Tipo Footer['dynamicColumns'] ya existe en payload-types.ts (confirmado, generado por la migracion de Phase 10.5): array de { title?: string, source: 'latestPosts' | 'latestCaseStudies', limit?: number, id?: string }.

Rutas de destino ya usadas en el codebase (PostCard.tsx, CaseStudyCard.tsx, CMSLink.tsx): /blog/{slug} para posts, /case-studies/{slug} para case studies (ver el mapeo collectionPath en src/components/CMSLink.tsx para el patron de conversion relationTo -> path).

- payload.findGlobal({ slug: 'footer', depth: 1, locale }) ya se llama.
- El grid de columnas manuales usa "grid-cols-2 md:grid-cols-4 gap-8" — esto NO es mobile-first (2 columnas ya en mobile es apretado con textos largos en ES) y debe cambiar a grid-cols-1 en el breakpoint base.
- Los titulos de columna usan text-label (plano) en vez de font-heading.
- El bloque de social/legal links usa flex-wrap — revisar que apile limpio en mobile.
