# Phase 13 — UI Design Contract

> Visual and interaction contract for the `AboutSection` features grid + CTA, the `FAQ` block's home placement, and the new admin icon-picker field. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (already initialized — `components.json` present since Phase 1) |
| Preset | `style: new-york`, `baseColor: neutral`, `cssVariables: true`, no prefix |
| Component library | Radix primitives via shadcn (`Button`, `Card` already installed under `src/components/ui/`; `Dialog` is NOT yet installed — required net-new for the admin icon picker, see Registry Safety) |
| Icon library | lucide-react only — matches `iconMap`/`socialIconMap` pattern already in `AuthorCard.tsx`/`SiteFooter` |
| Font | `font-heading` = Khand (`--font-khand`), body = Geist Sans (`--font-geist-sans`) — both already wired in `tailwind.config.ts`, no new fonts for this phase |

`ui-ux-pro-max` was not reachable as an invocable tool in this session (not present as a project skill, not resolvable via `npx`/Context7). In its place, the same design reasoning the project has already applied consistently since Phase 7/12 is used here: Minimalism/Swiss direction, monochrome neutrals + single accent, 150–400ms transitions, WCAG AA target. No new visual system is introduced — this phase composes strictly on Phase 7/8 tokens, matching CONTEXT.md's explicit lock.

**4-item feature grid — the pattern decision:** a 4-item "approach/methodology" grid is easy to over-design (heavy cards, oversized icons, 4-across desktop layouts that starve description text). This spec locks a **borderless, icon-anchored 2-column grid** (not bordered `Card` components):
- Borderless keeps the feature grid visually distinct from the site's actual card surfaces (case studies, education cards from Phase 12) — those represent discrete content entities; these 4 items are facets of one continuous "approach" narrative, so treating them as one flowing grid (icon + text, no boxes/borders) is the correct hierarchy signal.
- 2 columns (not 4) at `md:` and staying at 2 columns through `xl:` — the real ES copy runs ~90–130 characters per description; 4 columns at 1280px gives each card ~280px of width, which forces 4–5 line paragraphs and looks cramped. 2 columns gives each item enough width to read as 2–3 relaxed lines at all viewports ≥768px.
- 1 column on mobile (< 640px) — standard mobile-first stacking, confirmed against the 375px baseline.

## Spacing Scale

Declared values (must be multiples of 4) — inherited from Phase 7/8, no new scale introduced:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-box-to-title gap inside each feature item |
| sm | 8px | Icon-box internal centering, search-input icon gap (admin picker) |
| md | 16px | Feature title-to-description gap fallback, icon picker modal internal padding |
| lg | 24px | Feature grid gap (`gap-6`), icon-box size baseline area |
| xl | 32px | Feature grid outer padding on `sm:`/`md:` (`px-8` equivalent via existing `Container`) |
| 2xl | 48px | Spacing between existing `AboutSection` paragraphs and the new features grid (`mt-12`) — same value used for section breaks in Phase 12 |
| 3xl | 64px | Spacing between `AboutSection` and `FAQ` block on the home page layout (`py-12` per block × existing `Container` rhythm, no override needed) |

Exceptions: the admin icon-picker's icon buttons inside the modal grid use a 44px minimum touch target (`size-11`) even though the public-site 8-point scale otherwise governs — this is the standard accessibility exception for clickable icon-only controls, matching how touch-target exceptions are already called out in the template.

## Color

Inherited from Phase 7/8 tokens (`globals.css` `:root`/`.dark`) — no new colors introduced:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` (`#FAFAF7` light / `#12141C` dark) | Page background |
| Secondary (30%) | `--card` / `--muted` (`#FAFAF7`/`oklch(0.97 0 0)` light, `#1B1E29`/`#1F2230` dark) | Not introduced as a card surface in this phase (grid is borderless); `--muted` is not used here either — see accent note below |
| Accent (10%) | `--primary` (`#F7581E` light / `#FF7A45` dark, "ember") | Feature icon glyph + icon-box tint (`bg-primary/10` box, `text-primary` icon — 4 small instances), the existing `AboutSection` eyebrow (pre-existing, unchanged), and the new CTA button (`Button` default variant, `bg-primary`) |
| Destructive | `--destructive` (`#DC2626` light / `#F87171` dark) | Not used in this phase — no destructive actions exist on the public home page. The admin icon picker introduces no destructive action either (selecting an icon is not destructive; it just sets a field value) |

Accent reserved for: **feature icon glyphs/icon-box tint (4 instances, small surface area — box is `size-10`/40px), the pre-existing eyebrow text, and the CTA button** — nothing else in this phase touches `--primary`. Feature titles and descriptions stay on `foreground`/`muted-foreground` (neutral), matching the discipline already established in Phase 12 (badges kept `variant="secondary"`, not primary-colored, to protect the accent budget). Do not tint the icon-box background beyond `bg-primary/10` — a solid `bg-primary` box behind 4 icons would push accent well past 10% of the section's visual weight.

Dark mode: all values above already have verified `.dark` counterparts in `globals.css` — this phase makes zero new token additions, so dark-mode parity is automatic. Verify visually: `bg-primary/10` icon-box tint stays legible against `--card`/`--background` in both themes (ember-on-navy in dark mode has more contrast headroom than ember-on-off-white in light mode — check the icon-box tint doesn't wash out in light mode at low opacity).

## Section Specs

### 1. AboutSection features grid + CTA (public site)

Extends the existing component — the eyebrow/title/paragraphs/photo grid is unchanged; the features grid and CTA render below it, full-width, inside the same `Container`:

```tsx
import { TrendingUp, Zap, Code, Monitor } from 'lucide-react'
import { Button } from '@/components/ui/button'

const iconMap = { trendingUp: TrendingUp, zap: Zap, code: Code, monitor: Monitor } as const

// ...inside AboutSectionComponent, after the existing grid closes:
{features && features.length > 0 && (
  <div className="mt-12 grid grid-cols-1 sm:grid-cols-2 gap-6">
    {features.map((item, i) => {
      const Icon = iconMap[item.icon as keyof typeof iconMap] ?? Code
      return (
        <div key={i} className="flex gap-4">
          <div className="flex size-10 shrink-0 items-center justify-center rounded-md bg-primary/10">
            <Icon className="size-5 text-primary" />
          </div>
          <div>
            <p className="font-heading text-body font-semibold">{item.title}</p>
            <p className="mt-1 text-body text-muted-foreground">{item.description}</p>
          </div>
        </div>
      )
    })}
  </div>
)}
{ctaText && ctaLink && (
  <div className="mt-8">
    <Button asChild>
      <a href={ctaLink}>{ctaText}</a>
    </Button>
  </div>
)}
```

- Grid: `grid-cols-1 sm:grid-cols-2 gap-6` — 1 column below 640px, 2 columns from 640px through 1280px+ (deliberately does NOT go to 3 or 4 columns at any breakpoint — see the pattern-decision note above). Verify at 375px (single column, icon+text stacked, no cramping against real ES copy — "Optimización profunda de infraestructura, Rendering y esquema (Schema)..." must wrap cleanly across 2–3 lines) and at 768/1280px (2 columns, each ~340–580px wide, description text should read as 2–3 relaxed lines, not wrap awkwardly one-word-per-line).
- Icon box: `size-10` (40px) `rounded-md bg-primary/10`, icon `size-5 text-primary` — smaller than Phase 12's education `size-12` logo box (that page's cards carry more content weight; these are compact list items, not cards).
- Feature item is NOT wrapped in `Card` — borderless by design (see pattern-decision note). Do not add `border`, `shadow-*`, or `bg-card` to individual feature items.
- Icon-to-text gap: `gap-4` (16px, matches Phase 12's education-card icon gap).
- Title-to-description gap: `mt-1` (4px) — tighter than the 16px used for `AboutSection`'s own paragraph spacing, since these are compact list items with a strong title/body pairing, not standalone paragraphs.
- Spacing above the grid (from the existing paragraphs block): `mt-12` (48px) — matches the "major section break" token, since the features grid is a distinct sub-section within `AboutSection`, not a continuation of the same paragraph flow.
- CTA button: `Button` default variant (primary/ember), default size, `asChild` wrapping a plain `<a href="#contact">` — matches the project's existing pattern of anchor-link CTAs (no client-side smooth-scroll JS needed; native anchor navigation to `id="contact"` on `ContactFormBlock`, already present on the home layout). Spacing above CTA: `mt-8` (32px) — separates it from the grid as its own action, one step below the 48px major-break token since it's still part of the same "approach" section, not a new section.
- Rendering contract: features grid renders only if `features` is a non-empty array (mirrors the `photo` conditional already in the component); CTA renders only if both `ctaText` AND `ctaLink` are present — do not render a CTA with only one of the two set.
- Mobile-first breakpoints to verify: 375px (1-col grid, full-width CTA is NOT required — button stays intrinsic width, left-aligned, matching `Button`'s default inline-flex sizing, no `w-full` override), 768px (2-col grid), 1280px (2-col grid, confirm the 2-column choice doesn't leave excessive empty right-side space — if it visually reads too narrow/left-heavy at 1280px, the existing `md:col-span-7` outer constraint from the eyebrow/title/paragraphs half of the block does NOT apply here since the features grid spans full width — verify visually that a 2-col grid at full container width (not constrained to 7/12 columns) reads balanced, not sparse).

### 2. FAQ block on Home (no redesign)

No component changes required. `src/blocks/FAQ/Component.tsx` already renders with token-compliant classes (`font-heading text-heading`, `text-body`, `text-primary` on the `+`/`×` toggle glyph, `divide-border`, `transition-transform`). This phase's only FAQ-related work is:
- Add the `faq` block to the Home page's `layout` array (seed script), positioned at the end, before `ContactFormBlock` (per CONTEXT.md's locked order).
- Populate `title` + 5 real `faqs[]` entries (ES verbatim + EN translation per CONTEXT.md `<specifics>`).

Verification-only checklist for this block (confirm, don't redesign):
- `+` glyph rotates to `×` (45°) on `<details open>` via `group-open:rotate-45` — confirm this still reads correctly against the current `--primary` ember tone in both themes.
- `divide-y divide-border` row separators are visible in both light and dark mode (border token has explicit dark value — should already pass).
- At 375px, question text (`font-semibold text-body`) + the toggle glyph on the same flex row (`justify-between`) do not overlap or wrap into the glyph — the 5 real ES questions run up to ~85 characters (e.g. "¿Cuál es la diferencia entre el SEO tradicional y tu consultoría de SEO Técnico?"), confirm this wraps to 2 lines cleanly at 375px without crowding the `+` icon (it should stay top-aligned or vertically centered against the first line, not the wrapped block's center — if the current flex layout centers it against the full 2-line block awkwardly, that's the one adjustment in-scope, otherwise leave as-is).

## Admin Icon Picker (Payload dashboard — separate design system, non-blocking)

This is an **admin-UI component**, not a public-site component. It is explicitly out of scope for the public-facing design contract above (spacing/typography/color tables on this page govern the frontend only) and is **left to implementation discretion** per CONTEXT.md — this section exists only to make sure the spec doesn't silently block planning/execution on it.

**Before building:** verify whether the Payload admin route group (`src/app/(payload)/...`) imports the site's `globals.css` (shadcn tokens) or runs Payload's own default admin styling (`@payloadcms/ui` SCSS design system) unmodified. This determines which primitives are usable:

- **If shadcn/Tailwind IS available inside the admin route:** use `Dialog` (not yet installed — run `npx shadcn add dialog` first, official registry, no vetting gate needed) as the modal shell, an `Input` (already installed) for the search field, and a scrollable icon grid (`grid-cols-6 sm:grid-cols-8 gap-2` — a reasonable starting recipe, not a pixel mandate) of icon buttons inside. Each icon button: `size-11` (44px touch target exception, see Spacing Scale), selected state indicated with `ring-2 ring-primary`, click sets the field's string value and closes the dialog.
- **If shadcn/Tailwind is NOT available inside the admin route** (Payload admin commonly runs its own isolated CSS, especially for `admin.components.Field` overrides that don't opt into the frontend's Tailwind build): use `@payloadcms/ui`'s own `Modal`/`Popup` primitives (Payload ships these for exactly this kind of custom-field UI) styled to visually match Payload's default admin theme — a modal with a search input and an icon grid, same interaction shape as above, just built on Payload's own component kit instead of shadcn.

Either path satisfies CONTEXT.md's requirement ("popup/modal con grid visual de todos los iconos disponibles... buscador simple por nombre, preview visual de cada ícono, click para seleccionar"). The icon set offered: at minimum the 8 already-decided-relevant icons (`Zap`, `Monitor`, `Code`, `TrendingUp`, `Shield`, `Rocket`, `Palette`, `Lightbulb` — per CONTEXT.md's Claude's Discretion note) plus a reasonable broader lucide-react set. Saved value remains the icon's string name, compatible with the existing `iconMap` string-keyed lookup pattern used on the frontend (`ContactFormBlock`, `AuthorCard`, and now `AboutSection`).

This component does not touch the Checker Sign-Off dimensions below (those govern the public site only) — it is verified functionally (search filters correctly, click selects and closes, selected value persists) rather than against the color/spacing/typography contract.
