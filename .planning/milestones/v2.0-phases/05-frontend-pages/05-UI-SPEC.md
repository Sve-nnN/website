## Implementation Note — shadcn Gate Result

No design system exists yet in `juan-payload`: no `components.json`, no Tailwind config, no CSS file, no UI-related dependency in `package.json` (confirmed by direct repo scan). This is a clean slate.

Per the shadcn gate, shadcn is strongly recommended here — it gives Payload's block-driven React components (the hard rule below) a consistent primitive layer (Radix + Tailwind) without hand-rolling accessibility. Because this research agent does not have an interactive channel to receive a pasted `ui.shadcn.com/create` preset string from Juan, and because running `npx shadcn init` mutates `package.json`/creates `tailwind.config`/`components.json` (a repo-wide, semi-irreversible change), that command is **not executed by this research pass**. It is specified here as a locked recommendation and must be the first task of the first Phase 5 plan:

```bash
npx shadcn@latest init
# When prompted:
# style: New York
# base color: Neutral
# CSS variables: yes
# icon library: lucide-react (default with New York style)
```

If Juan prefers a different preset from `ui.shadcn.com/create`, he can paste it before that plan executes — swap the command for `npx shadcn init --preset {paste}`. Absent that, the values below are the contract.

## HARD RULE — Payload Block-Editability Constraint

**Every visual component and section on every page must be modeled as an editable Payload block, collection field, or global. Nothing about visual structure, copy, or imagery may be hardcoded in a React component.** This is non-negotiable per 05-CONTEXT.md and applies to home, blog, case studies, authors, contact, privacy, terms, search — no exceptions, including footer, nav, CTAs, and the author byline.

This is a design constraint, not just a build constraint: it shapes what "the design" is allowed to assume. A component may define *layout and style* (grid, spacing, typography, color), but never *content* (which posts are featured, what the CTA says, which credentials show). Concretely:

### Existing Payload artifacts this phase renders (already built, Phase 1/4)
Collections: `pages`, `posts`, `authors`, `case-studies`, `categories`, `media`, `testimonials`, `clientes`, `users`.
Blocks already registered on `Pages`: `Hero`, `Content`, `ArchiveBlock`, `CallToAction`, `FAQ`, `MediaBlock`, `TestimonialsCarousel`, `ContactFormBlock`, `Code`, `RelatedPosts`, `TableOfContentsBlock`, `ResultsSection`, `Section`.

### New Payload artifacts this phase must introduce (planner: treat as required tasks, not optional)

| Gap | What's missing | Required fix |
|---|---|---|
| No site chrome control | Nav links, logo, footer columns, social links, legal links are not editable anywhere | New `Header` global (nav items, CTA button) and `Footer` global (columns, legal links, social links) |
| Featured posts (CONT-03) | `posts` has no `featured` flag or curation mechanism; CONTEXT.md requires editors to choose which posts are featured, not just "most recent" | Add `featured: checkbox` to `Posts`, OR a `FeaturedContent` global with manual relationship arrays (`featuredPosts`, `featuredCaseStudies`) — recommend the global, since it also solves home-page featured case studies/clients without touching collection schema twice |
| Blog archive filter header copy | The "BlogArchiveHeader" concept from the old site has no Payload analog — category filter chrome (heading, description) is currently nowhere | Either a small `blogIndex` group of fields on a dedicated `pages` doc (slug `blog`) or a lightweight `BlogSettings` global — recommend reusing the `Pages` collection: the `/blog` route is a `pages` doc with `slug: "blog"` composed from `Hero` + a new `FeaturedPostsBlock` + a new `PostsArchiveBlock` (category-filterable) |
| E-E-A-T author expansion (CONT-02, explicit competitive differentiator) | `Authors` collection today only has `name`, `jobTitle`, `bio`, `avatar`, `slug` — CONTEXT.md explicitly requires going beyond this | Add to `Authors`: `credentials` (array of `{ label: text }`, e.g. "10+ años en SEO técnico", "Certificación Google Analytics"), `yearsExperience` (number, optional), `socialLinks` (array of `{ platform: select, url: text }` — LinkedIn/GitHub/X at minimum) |
| Search (CONT-04) | `@payloadcms/plugin-search` is not installed | Install + configure indexing on `posts`, `case-studies`, `authors`; a `/search` page renders results — no new content-editable UI needed here beyond the empty/error states below |
| Contact form copy | `ContactFormBlock` exists as a block config but its field labels/success/error copy must come from the block's own fields (already true), not hardcoded in the React renderer | Confirm renderer reads all copy from block fields — treat as an executor checklist item |

Any plan in Phase 5 that renders text, an image, a label, or a "which N items show" decision by reading a JS constant or a hardcoded string instead of a Payload field must be treated as a deviation from this contract, flagged the same way a missing test would be.

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (recommended, init deferred — see Implementation Note) |
| Preset | New York style / Neutral base color / CSS variables / radius `0.5rem` |
| Component library | Radix (via shadcn) |
| Icon library | `lucide-react` |
| Font | Body/UI: **Inter** (variable, `next/font/google`) · Display/Headings: **Fraunces** (variable serif, `next/font/google`) |

**Why this direction (research-informed):** the old site already used a serif display face over sans body for hero titles (`font-array, serif`) to signal editorial weight. Research on senior-engineer and consultant portfolios in 2026 (DesignRush, Awwwards portfolio category, CareerFoundry) converges on two winning directions: a "Terminal/premium-engineering" minimal-tech look, or an editorial/case-study-led look with strong typographic contrast and problem→outcome-first storytelling. Given Juan's dual positioning (engineer + SEO expert) and the case-study-driven content model already built in Phase 1, the editorial-tech direction is the better fit: sans UI type for legibility and density (tables, KPI cards, nav), serif display type for hero/section headlines to carry authority and differentiate from generic SaaS-blue templates. This is a refinement of the old site's instinct, not a reversal of it.

## Spacing Scale

Declared values (multiples of 4 only):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge/tag inline padding |
| sm | 8px | Compact element spacing (byline meta chips, KPI card internal gaps) |
| md | 16px | Default element spacing (form fields, card padding) |
| lg | 24px | Section-internal padding (card grid gutters, blog card padding) |
| xl | 32px | Layout gaps (grid row gaps, header/content separation) |
| 2xl | 48px | Major section breaks (between page sections: hero → featured → archive) |
| 3xl | 64px | Page-level spacing (top/bottom page padding, hero vertical padding on desktop) |

Exceptions: icon-only buttons (nav search trigger, mobile menu toggle, social icons in footer) use a 44px touch target regardless of visual icon size (accessibility minimum), padding computed to center the icon within that 44px box.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (Inter Regular) | 1.5 |
| Label | 14px | 600 (Inter Semibold) | 1.4 |
| Heading | 28px | 600 (Fraunces Semibold) | 1.2 |
| Display | 56px | 600 (Fraunces Semibold) | 1.05 |

Only 4 sizes and 2 weight families declared. Responsive scaling note (not a new size token, a clamp on the existing tokens): Display scales down to 36px and Heading to 22px on mobile viewports (<640px) via CSS `clamp()`, never via a separate token. KPI numbers in case-study result cards reuse the Display size at Heading's weight (600) to stay within the 4-size budget.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FAFAF7` (warm off-white) | Page background, default surface, body copy areas |
| Secondary (30%) | `#12141C` (near-black ink navy) | Header/nav bar, footer, hero background/overlay, case-study KPI card backgrounds, dark section breaks |
| Accent (10%) | `#FF5B1F` (ember orange) | Reserved for: primary CTA button fill, active nav-link underline/indicator, in-body link color, category tag active state, KPI metric numbers/before-after deltas in case studies, search result highlight |
| Destructive | `#DC2626` | Reserved for: contact form field validation error border/text, form-level error banner border — there are no other destructive user actions on this public, read-only-content frontend |

Accent reserved for: primary CTA button, active nav indicator, in-copy links (`<a>` inside rich text), active category filter chip, case-study KPI numbers/deltas, search match highlight. Never applied to decorative elements, illustrations, or as a background fill for large surfaces — it stays a signal color, not a paint color.
