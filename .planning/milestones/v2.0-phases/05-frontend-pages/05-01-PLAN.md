If the CLI's current defaults differ from the shadcn 2.x preset it targets, follow the CLI's own version (it manages Tailwind v3-vs-v4 wiring correctly for the installed Next version) but explicitly select: style `new-york`, base color `neutral`, CSS variables `yes`, icon library `lucide-react` — these are the locked preset values from 05-UI-SPEC.md's Design System table. This creates/updates `components.json`, `src/lib/utils.ts` (the `cn()` helper), and either `tailwind.config.ts` or a CSS-first Tailwind v4 setup in `src/app/globals.css` — accept whichever the installed shadcn/Tailwind version produces, do not hand-roll a conflicting config.

Add Inter (variable) and Fraunces (variable, serif) via `next/font/google` in `src/app/(frontend)/[locale]/layout.tsx`: import both, expose as CSS variables (e.g. `--font-sans` for Inter, `--font-display` for Fraunces), apply the variable classes to the `<html>` or `<body>` tag alongside existing `NextIntlClientProvider` wiring — do not remove the existing locale/`notFound()`/`setRequestLocale` logic already in that file.

In the Tailwind theme (`tailwind.config.ts` theme.extend, or the CSS `@theme` block if shadcn produced Tailwind v4 CSS-first config), declare:
- `fontFamily.sans` → Inter variable, `fontFamily.display` → Fraunces variable (per UI-SPEC Design System row).
- Color tokens per 05-UI-SPEC.md Color table: dominant `#FAFAF7`, secondary `#12141C`, accent `#FF5B1F`, destructive `#DC2626` — wire these as shadcn's existing CSS-variable slots (`--background`, `--foreground`, `--primary`, `--accent`, `--destructive`, etc. — map dominant→background, secondary→a `--secondary`/dark-surface token used for header/footer/hero-overlay, accent→`--primary` since it's the CTA/link/active-indicator color per spec) rather than inventing a parallel token system.
- Spacing tokens per UI-SPEC Spacing Scale table (xs 4px, sm 8px, md 16px, lg 24px, xl 32px, 2xl 48px, 3xl 64px) — these already exist as Tailwind's default `4,2,6,8,12,16` etc. spacing scale multiples of 4; do not add a redundant custom scale, just document in a code comment which Tailwind spacing utility maps to which named token (e.g. `p-4`=md, `py-16`=3xl) so downstream plans use consistent utilities.
- Typography per UI-SPEC Typography table (Body 16/400/1.5, Label 14/600/1.4, Heading 28/600 Fraunces/1.2, Display 56/600 Fraunces/1.05, with Display clamping to 36px and Heading to 22px under 640px via CSS `clamp()`) — add these as Tailwind `fontSize` theme keys (`text-body`, `text-label`, `text-heading` using a `clamp(1.375rem, ..., 1.75rem)` value, `text-display` using `clamp(2.25rem, ..., 3.5rem)`), each pinned to its declared line-height and paired with the correct `fontFamily` (heading/display use `font-display`).
  </action>
