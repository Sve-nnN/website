Reference-only (do not copy verbatim, different collection scope): JuanPortfolio's `src/plugins/index.ts` registers `searchPlugin({ collections: ['posts'], beforeSync, searchOverrides: { fields: ({defaultFields}) => [...defaultFields, ...searchFields] } })`, and `src/search/beforeSync.ts` populates `slug`/`meta`/`categories` on the synced search doc, resolving category relationships to `{relationTo, categoryID, title}` pairs via `req.payload.findByID`. This project extends the same shape across 3 `relationTo` targets (`posts`, `case-studies`, `authors`) instead of 1 — `beforeSync` must branch on `searchDoc.doc.relationTo` to know which source-collection fields are available (e.g. `authors` docs have no `categories`).

UI-SPEC Copywriting Contract: empty search (no query yet) heading "No results for "{query}""/"Sin resultados para "{query}"" — this is actually the zero-*results* state, not the empty-query landing state; use it only when a query was submitted and returned 0 docs. Error state (search backend failure): "Search is temporarily unavailable. Please try again in a moment."/"La búsqueda no está disponible por el momento. Intenta de nuevo en unos minutos."
</interfaces>

| T-05-11-01 | Tampering | `search/page.tsx` query param | mitigate | Use Payload's parameterized `like` operator (never string-concatenated raw SQL); Payload's Postgres adapter parameterizes `where` clauses by construction |
| T-05-11-02 | Denial of Service | Unbounded/very long `?q=` values | mitigate | Cap query length (e.g. truncate to 200 chars) before passing to `payload.find` to bound query cost |
