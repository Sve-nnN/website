## Component Inventory

### Section shell (`ServicesShowcaseComponent`)

- `<Container className="py-12">` — identical wrapper to `FeaturedCaseStudiesBlockComponent`/`FeaturedPostsBlockComponent`.
- `{title && <h2 className="font-heading text-heading mb-6">{title}</h2>}` — exact same conditional pattern, same classes, same field name (`title`, localized `text`, no default). No subtitle field, no section-level CTA link — the block already shows all 4 services, so there is nothing to "view more" of.
- Grid: `<div className="grid grid-cols-1 sm:grid-cols-2 gap-6">`

  **Grid decision (resolves SVCHOME discretion point):** 2×2, not 4-in-a-row. `grid-cols-1 sm:grid-cols-2` (stays 2 columns from `sm` through `lg` and beyond — no `lg:grid-cols-4` override). Rationale: each card carries an icon badge + `h3` title + 2-line description + CTA row, i.e. more content than `CaseStudyCard` (title + sector + metric, no description) or `PostCard` (image-led, 2-line excerpt only). At the `Container`'s `max-w-6xl` (1152px), 4-across would give ~228px per card after gaps — too narrow for a 16px/1.5 two-line description without heavy wrapping. 2×2 matches `AboutSectionComponent`'s own `sm:grid-cols-2` features grid, keeping the breakpoint behavior consistent with the block this pattern was borrowed from.

### Card (`ServiceShowcaseCard` — new, colocated in `src/blocks/ServicesShowcase/`, not `src/components/` since it has no reuse outside this block)

```
<Link href={serviceHref} className="group block">
  <Card>
    <CardContent className="p-6">
      <div className="flex size-10 shrink-0 items-center justify-center rounded-md bg-primary/10">
        <Icon className="size-5 text-primary" />
      </div>
      <h3 className="font-heading text-heading mt-4">{page.title}</h3>
      {excerpt && (
        <p className="mt-2 text-body text-muted-foreground line-clamp-2">{excerpt}</p>
      )}
      <div className="mt-4 flex items-center gap-1 text-label text-primary">
        <span>{ctaLabel}</span>
        <ArrowRight className="size-4 transition-transform duration-fast ease-standard group-hover:translate-x-1" />
      </div>
    </CardContent>
  </Card>
</Link>
```

**Icon/image decision (resolves SVCHOME discretion point):** icon badge, not a photo, and not text-only. Rationale:
- Text-only (à la `CaseStudyCard`) was rejected because `CaseStudyCard` compensates with a `heroMetric` headline-stat number, and `PostCard` compensates with a hero photo — every existing card in this grid vocabulary has *some* visual differentiator beyond title+text. A 4-card service grid with zero differentiator between cards would be the flattest card treatment on the site, on the page (Home) that gets the most traffic.
- A real photo/hero image was rejected because the `pages` collection has no dedicated card-thumbnail field (only `title`, `content.layout`, and `meta` from the SEO plugin) — CONTEXT explicitly scopes card copy to `page.title` + `page.meta?.description`, and reaching into each service page's nested `Hero` block to extract an image would add fragile coupling this phase's aditive/no-schema-touch mandate does not ask for.
- Icon badge was chosen because it is **already an established pattern in this exact codebase** (`AboutSectionComponent`'s features grid: `size-10 rounded-md bg-primary/10` badge + `size-5 text-primary` icon), requires **no Payload schema change** (no new field on `pages`), and gives each of the 4 cards a distinct, semantically-appropriate glyph.
- Icon selection is a **hardcoded slug→icon map colocated in the block's `Component.tsx`**, sourced from the existing `ICON_OPTIONS` set (`src/fields/IconPicker/icons.ts`) — not a new admin-editable field, since CONTEXT's data-source decision (`SERVICE_SLUGS`-driven fetch, no curated relation) applies to icon selection too:

  | Slug | Icon (`ICON_OPTIONS` value) | Rationale |
  |------|------------------------------|-----------|
  | `seo-technical-audit` | `search` (`Search`) | Audit = finding/diagnosing |
  | `seo-consulting` | `trendingUp` (`TrendingUp`) | Consulting = growth/strategy |
  | `fullstack-development` | `code` (`Code`) | Matches the icon already used in `AboutSectionComponent`'s fallback and its own dev-related feature |
  | `ai-seo-geo` | `sparkles` (`Sparkles`) | AI/GEO = the "new/emerging" service, sparkles reads as AI-coded across the rest of the site's icon usage |

  Fallback for any unmapped slug: `code` (`Code`), same fallback icon `AboutSectionComponent` already uses.

**Excerpt source:** `page.meta?.description` (falls back to omitting the `<p>` entirely if absent — same optional-field guard pattern as `caseStudy.sector`/`caseStudy.heroMetric` in `CaseStudyCard`). Truncate visually with `line-clamp-2` (same utility `PostCard` already uses), not by slicing the string server-side — keeps the source data untouched.

**Card link target:** each card is a full-bleed `<Link>` wrapper (`group block`), matching `PostCard`/`CaseStudyCard` exactly — no separate "read more" button, the whole card is clickable. Href built via the same dual-segment locale pattern already used by `src/lib/canonical.ts` (`/servicios/{slug}` in `es`, `/services/{slug}` in `en`).

**Elevation/motion:** zero new values — `Card` already carries `shadow-sm ... hover:shadow-md transition-shadow duration-base ease-standard` from `src/components/ui/card.tsx` (Phase 8/10), inherited automatically, nothing to add in this block. The CTA-row arrow's `group-hover:translate-x-1` reuses `duration-fast`/`ease-standard`, the same token pair `PostCard`'s image-scale hover already uses.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Section title (`title` field, localized, per-instance, no hardcoded default) | ES: "Servicios" or a stronger variant chosen at seed time, e.g. "Cómo puedo ayudarte" — EN: "Services" / "How I can help" — **final exact string is a seed-script decision** grounded in the real Home copy voice already established by `AboutSection`/`Hero`; this contract requires only that it is a real, non-generic sentence, not a placeholder, populated by the Phase 24 seed script per CONTEXT |
| Card title | `page.title` verbatim (no rewrite) — e.g. "Auditoría SEO Técnica" / "SEO Technical Audit" |
| Card excerpt | `page.meta?.description` verbatim, truncated visually to 2 lines via `line-clamp-2` — no new copy authored by this phase, reuses what Phase 19's SEO population already wrote |
| Card CTA (`ctaLabel`) | ES: "Explorar servicio" — EN: "Explore service" — hardcoded per-locale via `next-intl` message keys (not a Payload field; consistent across all 4 cards, no per-card override) |
| Empty state | If `getServicePage` fails to resolve one of the 4 `SERVICE_SLUGS` for the active locale, that card is silently omitted (`.filter(Boolean)` pattern, same as `FeaturedCaseStudiesBlockComponent`'s `caseStudies.filter(...)`); if all 4 resolve to nothing, the whole block returns `null` (same `if (...length === 0) return null` guard already used by both precedent blocks) — no "no services" empty-state copy needed, this is a fixed-content block, not a query-driven list that can legitimately be empty in production |
| Error state | Not applicable — server component, no client-side fetch/error boundary introduced; a resolution failure degrades to the "omit that card" behavior above, never a visible error message |
| Destructive confirmation | Not applicable — no destructive action in this block |
