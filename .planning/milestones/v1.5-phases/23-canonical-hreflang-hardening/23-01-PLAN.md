<objective>
Close the dual-slug duplicate-content gap on Servicios: the 4 physical URL combinations (`es`+`/servicios`, `es`+`/services`, `en`+`/servicios`, `en`+`/services`) currently render byte-identical content with zero `rel=canonical` and zero `hreflang` anywhere in `<head>` (confirmed by RESEARCH.md PITFALLS.md — `grep alternates|canonical src/app` matches only sitemap route files, never page metadata). This plan adds a pure shared helper that builds canonical + reciprocal hreflang alternates purely from `locale` (so canonical always resolves to the locale-correct segment regardless of which physical folder rendered the page — the exact mechanism that collapses 4 URLs into 2 canonical targets), wires it into all 4 Servicios `generateMetadata` functions, and sets `metadataBase` once in the frontend root layout (`[locale]/layout.tsx` — there is no `src/app/layout.tsx`, this file is the actual root of the public site tree).

Purpose: SEOTECH-01/02/03 — stop fragmenting ranking signal for the site's highest-intent pages before Phase 25's visual redesign makes the gap more visible.
Output: `src/lib/canonical.ts` (new pure module), `metadataBase` in the frontend layout, `alternates` wired into the 4 Servicios `page.tsx` files, live curl-verified against the running dev server.
</objective>
