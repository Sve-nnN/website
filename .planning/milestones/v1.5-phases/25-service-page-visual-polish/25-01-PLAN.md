  <action>
Write `scripts/capture-service-page-snapshot.mjs` as a standalone Node script (ESM, no Payload/DB import — pure HTTP fetch + HTML parsing) that:
1. Accepts `--base-url` (default `http://localhost:3000`) and `--out <path>` CLI args (same parsing style as `lighthouse-mobile.mjs`).
2. Fetches the 8 URLs listed in the Interfaces section above.
3. For each URL: extracts every `<h1...>...</h1>` occurrence (regex or a lightweight HTML parse — no new npm dependency, use a simple tag-content regex tolerant of nested spans/classes) and records `{ count, texts: string[] }`.
4. Extracts every `<script type="application/ld+json">...</script>` block, `JSON.parse`s its contents, and records the parsed object's `@type` plus (for `BreadcrumbList`) the full `itemListElement` array (position/name/item per entry) verbatim.
5. Writes one JSON object keyed by URL path to `--out`, shape: `{ "<path>": { h1: { count, texts }, jsonLd: [{ type, raw }] } }`.
6. Logs a per-URL one-line summary to stdout (`<path>: h1Count=N jsonLdTypes=[...]`) and exits 1 if any URL fails to fetch or any H1 count is 0 (that would mean the current site already has a regression before this phase even starts — must not proceed silently).

Run it against the current dev server (`npm run dev` already running, or start one) with `--base-url http://localhost:3000 --out .planning/phases/25-service-page-visual-polish/25-baseline-content.json`.
  </action>
  <acceptance_criteria>
    - `.planning/phases/25-service-page-visual-polish/25-baseline-content.json` exists and contains exactly 8 top-level keys (one per URL above)
    - Every entry has `h1.count === 1` (today's Hero `variant: listing` renders exactly one H1 — a count of 0 or 2+ means the baseline capture itself is broken, must be fixed before proceeding)
    - Every entry's `jsonLd` array contains at least one object with `type === "BreadcrumbList"`
  </acceptance_criteria>
