## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-07 | Tampering | `reapplyIds` sub-array id matching | mitigate | Positional matching is guarded by a `blockType` equality check per index before copying `id` — if layout shape ever drifts between locales (should not happen, both are built from the same copy shape), the function skips id-reuse for that block instead of silently attaching a wrong id to unrelated content, which would otherwise risk corrupting an existing row's data on `update` |
| T-19-08 | Repudiation | Idempotent re-run behavior | accept | Script is local/developer-run only, not exposed to any HTTP endpoint or CI trigger — no untrusted party can invoke it; idempotency is a data-integrity property (Task 2 verifies it), not an access-control boundary |
| T-19-SC | Tampering | npm/pip/cargo installs | n/a | No new package installs in this plan — reuses `tsx`/`payload` already in `package.json` |

No new external input surface. This plan's only write path is the Local API, already covered by
`pages`' existing `authenticated` create/update access control (irrelevant here since the Local API
call itself is what performs the write, run by a trusted developer, not through the access-checked
HTTP/GraphQL API).
